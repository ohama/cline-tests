--- A defect this run surfaced, tracked for the record (see 11-06-SUMMARY.md for the full note) ---

`assert_budget`'s cap-triggered path calls `exit 1` directly from inside the sourced function,
which exits `run_ab.sh` immediately WITHOUT running its own `postflight11` call or writing its
manifest-closing block -- unlike every OTHER abort path in run_ab.sh (idle-timeout, runaway-guard,
the orchestrator's own providers.json-repair-failure hook), which set `ABORTED=1` and `break` out
of the loop, letting postflight11 and the manifest-close still run afterward. This run's
`postflight.txt` and the tail of its `manifest.txt` were therefore run/written MANUALLY by the
orchestrator immediately after the abort (same `postflight11` function, same run directory, run
within seconds of the abort so it reflects the true final state) rather than automatically by
`run_ab.sh` itself. The manual postflight11 call succeeded (exit 0): three `com.ohama.*` pids
unchanged, `providers.json` model=flashnext/contextWindow=29000, `verify_config.sh` exit 0,
`cline --version` stable at 3.0.61 before and after. This is recorded here as a real, minor defect
in `run_ab.sh`'s cap-abort path (not fixed in this plan, since fixing shared safety-envelope code
mid-evidentiary-run was judged riskier than manually reproducing its output once) -- a future user
of `run_ab.sh` should have this path changed to set `ABORTED=1`/`break` like its siblings rather
than calling `exit` directly, or the docstring updated to say plainly that a cap-abort skips
postflight and must be run by hand.
