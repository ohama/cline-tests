=== anti-orphan note ===
PPID=1 (launchd) directly, not an intermediate bash/wrapper process still alive:
the wrapper's own exec chain (run_kanban_service.sh 'exec run_sandboxed.sh' -> run_sandboxed.sh
'exec sandbox-exec -f profile -- kanban' -> kernel loads kanban's #!/usr/bin/env node shebang)
replaces the process image at every hop via execve(), so the pid launchd supervises
(pid=52654) is the SAME pid the whole way down -- this is why the args line above shows the
real 'node /opt/homebrew/bin/kanban ...' invocation directly, not bash and not a forked child
that could have exited leaving an orphan.
