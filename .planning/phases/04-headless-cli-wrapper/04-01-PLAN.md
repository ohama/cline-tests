<task type="auto">
  <name>Task 2: Write phase-04/classify_run.py</name>
  <files>phase-04/classify_run.py</files>
  <action>
Write the classifier, modelled directly on `phase-01/parse_result.py`'s discipline: stdlib only,
a **pure** `classify()` with no file I/O and no clock, plus a thin CLI.

Signature (this is a contract two other plans depend on — do not change it):
```
classify(events, cline_exit_code=None, stderr_text="", allowed_prefixes=None) -> Outcome
CLI: python3 phase-04/classify_run.py --ndjson <file> [--exit-code <int>] [--stderr <file>]
                                      [--allowed-prefix <path> ...] --out <dir>
     writes <dir>/outcome.json and <dir>/outcome.md
```

`Outcome` is a dataclass with fields: `outcome` (str, the single primary label), `signals`
(list[str], EVERY signature detected — outcomes are never collapsed, and a stream carrying two
signatures reports both here), `reason` (str), `finish_reason` (str|None), `tool_attempts`
(list of dicts: `tool_name`, `query`, `success`, `error`), `denied_targets` (list[str] — the
`query`/path strings from denied attempts), `malformed_lines` (int), `cline_exit_code` (int|None).

The six primary outcomes and their detection rules:
- `crashed` — no `run_result` event anywhere, OR `cline_exit_code is not None and
  cline_exit_code > 128`. This is the **false-pass guard**: same rule
  `phase-03/sandbox/assert_denied.sh` uses (signal death is a crash, never a denial). Reason text
  must say the result is inconclusive and must not be reported as a block.
- `sandbox_denied` — at least one tool `content_end` output entry with `success` false whose
  `error`/`result` text matches `EPERM|Operation not permitted|not permitted`.
- `context_overflow_terminal` — an `agent_event` error event whose message (see nested handling
  below) contains `MAX_KV_SIZE`, or matches `context tokens` plus a digit. Reason text must carry
  the operational rule verbatim from `docs/32k-compaction-policy.md` §3②: **terminal, not
  retryable — restart the task; do not wait or retry in place.**
- `tty_approval_rejected` — at least one tool output (object OR array entry) whose `error` matches
  `requires approval in a TTY session`. Reason text must say this is the **expected** behavior of
  the shipped `--auto-approve false` wrapper for any tool-using prompt, not a crash and not a
  sandbox event.
- `run_aborted` — a top-level `run_aborted` event or `run_result.finishReason == "aborted"`, with
  no TTY-approval signature.
- `success` — `run_result.finishReason == "completed"` and none of the above.
- `other` — anything else (keep it, don't force a wrong label).

Primary-outcome precedence, in this exact order, and stated in a module docstring comment so a
reader knows it was chosen, not accidental: `crashed` > `sandbox_denied` >
`context_overflow_terminal` > `tty_approval_rejected` > `run_aborted` > `success` > `other`.
`crashed` is first because an unusable stream can prove nothing; `sandbox_denied` outranks the
rest because it is the phase's positive signal and its signature (a real kernel EPERM) cannot be
produced by any of the others. Because `signals` lists every signature found, no information is
lost to this ordering.

Error-message extraction: copy `phase-01/parse_result.py`'s `_error_event_message()` — check flat
`event["message"]` first, then fall back to `event["error"]["message"]`. Cline 3.0.53 emits the
nested shape live; a flat-only reader silently misses every real 32K failure (Phase 1 hit exactly
this bug against real data).

Tool-output shape tolerance: `content_end.output` is an ARRAY of per-query dicts in the
success/denial shape and a bare OBJECT in the TTY-rejection shape. Normalize both to a list before
inspecting. Also tolerate a sibling top-level `event["error"]` string.

`allowed_prefixes` (optional): when supplied, `denied_targets` entries that start with one of the
prefixes are also flagged in `signals` as `denied_inside_allowlist` — a denial of a whitelisted
path means the sandbox is misconfigured, not that criterion 3 passed.

Exit code contract for the CLI, documented in the module docstring (house pattern: an explicit
numeric contract, callers grep it):
`0`=success, `2`=sandbox_denied, `3`=tty_approval_rejected, `4`=run_aborted,
`5`=context_overflow_terminal, `6`=other, `7`=crashed/inconclusive, `1`=classifier's own
usage/IO error.

`outcome.md` renders a short human-readable verdict with a Korean one-liner per outcome (mirroring
`parse_result.py`'s `_KOREAN_ONE_LINER`), the signals list, the tool-attempt table and the raw
denial/error payloads.
