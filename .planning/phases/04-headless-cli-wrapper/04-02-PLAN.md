<task type="auto">
  <name>Task 1: Write phase-04/run_headless.sh</name>
  <files>phase-04/run_headless.sh</files>
  <action>
Write the shipped wrapper. `#!/usr/bin/env bash`, `set -uo pipefail` (not `-e` around the live
run — a non-zero cline exit is DATA, exactly as `phase-01/run_regression.sh` documents). macOS
`/bin/bash` is 3.2: indexed arrays only, no `declare -A`.

**Header comment block, in this order — none of it buried:**
1. Usage and the exit-code contract (inherited from `phase-04/classify_run.py`: 0 success,
   2 sandbox_denied, 3 tty_approval_rejected, 4 run_aborted, 5 context_overflow_terminal,
   6 other, 7 crashed/inconclusive, 1 preflight abort).
2. **SHIPPED LIMITATION (stated, not hidden)** — in cline 3.0.53, `--auto-approve false` in
   `--json` / no-TTY mode does not pause for approval: it rejects **every** tool call outright
   with `Tool "<name>" requires approval in a TTY session`, and the run self-aborts after a few
   iterations. So **this wrapper is intentionally safe-but-inert for tool-using prompts**: it will
   refuse to act rather than act unsupervised. A prompt needing no tools completes normally. That
   is what HLS-02 taken literally produces; it is a real, shipped limitation, in scope for this
   milestone's one-shot smoke test ("서비스화는 이번 마일스톤에서 하지 않는다") and it is Phase 5's
   to revisit when the surfaces go live. Do not "fix" it by flipping the flag.
3. **THE CWD RULE (04-RESEARCH.md Pitfall 1)** — the OS-level process cwd must be inside
   `ALLOWED_REPOS.json` or Bun dies at startup with a path-less generic error. `cline -c/--cwd` is
   a separate, additional flag and does not substitute for it. A future launchd/cron caller with
   no `WorkingDirectory` will resurrect this crash and it will look exactly like a sandbox
   tightening — hence the explicit assertion below.
4. A pointer to `phase-04/verify_sandbox_via_cline.sh` as the deliberately-different,
   `--auto-approve true`, TEST-ONLY invocation that proves the sandbox boundary — and a line
   saying this wrapper must never call it and must never itself pass `--auto-approve true`.
5. **NEVER widen the sandbox from here.** `phase-03/sandbox/config.env`'s `EXTRA_ALLOW_PATHS` is
   the only sanctioned widening point, it is empty, and this wrapper's crash fix did not need it.

**Interface:**
```
run_headless.sh [--out-dir <dir>] [--timeout <secs>] [--] <prompt>
env: HEADLESS_DRY=1  DRY_FIXTURE=<path>  (offline: copy a fixture instead of invoking cline)
     RESULTS_ROOT=<dir>  SKIP_SANDBOX_GATE=1
```
Default timeout `1800` (`WRAPPER_TIMEOUT`/`--timeout`).

**Steps:**
1. `source phase-04/config.env` then `source phase-01/config/cline-invocation.env` (paths resolved
   from `BASH_SOURCE`, so the script works from any cwd).
2. `RESULTS_DIR="$RESULTS_ROOT/$(date -u +%Y%m%dT%H%M%SZ)-headless"`, `mkdir -p`. All diagnostics
   from here on go to **stderr**; stdout is reserved for NDJSON only.
3. Preflight A — config guard: `bash phase-01/config/verify_config.sh` (tee to
   `$RESULTS_DIR/config_pre.txt`). On failure, heal once with
   `bash phase-01/config/apply_provider_config.sh`, then re-verify; abort exit 1 if still failing.
   This is Phase 1's documented, live-reproduced drift (`models[]`/`contextWindow` stripped by any
   real cline invocation), not ceremony.
4. Preflight B — sandbox standing gate: unless `SKIP_SANDBOX_GATE=1`, run
   `bash phase-03/sandbox/verify_sandbox.sh --out-dir "$RESULTS_DIR/sandbox-gate"`. Abort exit 1
   unless it exits 0. `docs/sandbox-whitelist.md` §5 makes this the required gate before any phase
   trusts `run_sandboxed.sh`.
5. Working directory: `mkdir -p "$SANDBOX_WORKDIR"` (it is gitignored), `cd "$SANDBOX_WORKDIR"`,
   then **assert** with python3 that `$PWD` is a prefix-match of some `repos[]` entry in
   `ALLOWED_REPOS.json`; abort exit 1 with an explicit message if not. Record the result in
   `$RESULTS_DIR/workdir.txt`.
6. The run. Under `HEADLESS_DRY=1`, copy `$DRY_FIXTURE` (default
   `phase-04/fixtures/success_no_tools.ndjson`) to `$RESULTS_DIR/ndjson.log`, write
   `DRY_RUN` into `cline_exit.txt`, and skip to step 8. Otherwise, in ONE chained shell command
   (the reinstall-then-immediately-launch pattern — `CLINE_NO_AUTO_UPDATE=1` alone does not
   reliably stop the background self-update, Phase 1 finding):
```
npm install -g "cline@${CLINE_PINNED_VERSION}" >"$RESULTS_DIR/npm_pin.txt" 2>&1 && \
CLINE_NO_AUTO_UPDATE=1 "$RUN_SANDBOXED" -- "$CLINE_BIN" $CLINE_COMMON_FLAGS \
  --json --auto-approve false -t "$TIMEOUT" -c "$SANDBOX_WORKDIR" "$PROMPT" \
  2>"$RESULTS_DIR/stderr.log" | tee "$RESULTS_DIR/ndjson.log"
```
   `$CLINE_COMMON_FLAGS` is intentionally unquoted so bash word-splits it — this script is bash,
   never source it from zsh (Phase 1 decision 01-05). Capture `${PIPESTATUS[0]}` into
   `$RESULTS_DIR/cline_exit.txt` and echo a note to stderr that a non-zero value is data.
   **`--auto-approve false` must appear as those literal adjacent tokens** — criterion 2 is
   verified by grep, so no variable indirection, no `$AUTO_APPROVE`.
7. Post-run config guard: `verify_config.sh` → heal → re-verify, transcript to
   `$RESULTS_DIR/config_post.txt`. Record whether healing was needed; a heal is expected, not a
   failure.
8. Classify: `python3 "$PROJECT_ROOT/phase-04/classify_run.py" --ndjson "$RESULTS_DIR/ndjson.log"
   --exit-code "$CLINE_EXIT" --stderr "$RESULTS_DIR/stderr.log" --out "$RESULTS_DIR"`. Echo a
   single `RESULT: <outcome> — $RESULTS_DIR` line to **stderr** and exit with the classifier's
   exit code.
  </action>
  <verify>
`grep -c -- '--auto-approve false' phase-04/run_headless.sh` >= 1 AND

`grep -ci 'inert' phase-04/run_headless.sh` >= 1 (the limitation is stated in the shipped file).
`bash -n phase-04/run_headless.sh` exits 0.
  </verify>
  <done>The wrapper exists, hard-codes `--auto-approve false` as literal adjacent tokens, has exactly one cline invocation path and it goes through run_sandboxed.sh, and states the inert-for-tool-use limitation in its own header.</done>
