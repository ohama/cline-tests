<objective>
Run the A/B at the authorised size and report exactly what came back.

Purpose: USE-03's deliverable is a recorded, evidence-backed keep-or-revert decision. This plan
produces the evidence. It does not make the decision — plan 11-07 does, with a human — because
changing which alias `cline-plan` targets changes the default behaviour of a tool the user will
actually use.

Output: the main run directory with every raw stream, and `phase-11/AB-RESULTS.md`.

**Outcome neutrality, stated once and meant:** a result showing no improvement, or showing the
thinking arm is worse — slower, or degraded by completion-budget starvation — is a complete and
valid outcome. ROADMAP criterion 3 conditions success on the table and the recorded judgement
existing, not on their direction. Nothing in this plan may be retried, re-graded, re-scoped or
re-run because the numbers were disappointing. The only legitimate re-run is one the protocol's own
void conditions require, and a void run is reported as void.
</objective>

<hard_constraints>
1. **Never call the `flashnext-codex` alias.**
2. **Never restart** the three `com.ohama.*` services. **Nothing binds port 3000.**
3. **Do not edit** `providers.json`, the litellm config, or `~/local-llm-settings/`.
4. **Sequential only**, `in_flight=0` confirmed before every request. The model is shared with
   Kanban and Telegram.
5. **The request cap is whatever the human authorised in plan 11-05 Task 3**, recorded in
   `AB-PROTOCOL.md` §4, and it is enforced by `run_ab.sh`'s counter. Exceeding it aborts the run.
   If the run aborts on the cap, that is reported — the cap is not raised to finish the sweep.
6. **No retry for content.** Operational retries only, at most one per cell, marked in the row.
7. **bash 3.2**; `python3` stdlib only.
8. **Do not edit** the task set, the answer keys, or the grader's verdict logic during or after the
   run. If a grader defect is discovered mid-run, stop, record it, fix it, re-run the fixture
   self-test from plan 11-02, and re-grade **all** cells from the retained raw streams — never a
   subset, and never only the ones that looked wrong.
9. **Do not edit** `phase-11/AB-PROTOCOL.md`'s §5 decision rule. It is pre-registered. If it turns
   out to be inapplicable, say so in `AB-RESULTS.md` and explain why; do not amend it after seeing
   the data.
</hard_constraints>

Run `phase-11/run_ab.sh` with exactly the parameters the human authorised — task ids, arms, `--reps`,
`--cap` — reading them from `AB-PROTOCOL.md` §4 rather than from memory, and echo them into
`"$RUN"/manifest.txt` before the first request.

Before starting:
- Confirm `bash phase-01/config/verify_config.sh` exits 0 (it now also checks the wrappers).
- Confirm `in_flight=0` and record the `flashnext.err` byte watermark.
- Record `cline --version`.
- Record the three `com.ohama.*` pids.

`updatedAt`/sha, and `verify_config.sh`'s exit status. If the two version strings differ, the run is
**void** per protocol §3 — record it as void, keep every artefact, and report that as the outcome
rather than presenting numbers produced by two different binaries.

Finally, prove the aggregate is reproducible from the raw evidence: re-run `phase-11/grade_ab.py`
over every retained stream in a fresh pass and confirm the verdict column reproduces `ab.tsv`
exactly. Write the comparison to `"$RUN"/regrade-check.txt`. If any verdict differs, that is a
grader non-determinism bug and it blocks the results document until explained.

<task type="auto">
  <name>Task 2: AB-RESULTS.md — the table, the four categories, and the rule's mechanical output</name>
  <files>phase-11/AB-RESULTS.md</files>
  <action>
Write `phase-11/AB-RESULTS.md`, modelled on `phase-10/REACH-PROOF.md`'s structure. Sections:

**§1 What was run.** Arms and their aliases; the exact invocation shape; the task ids; N; the
authorised cap and the **actual measured request count**; the run directory path; both
`cline --version` readings; the live compaction trigger value in force. Note that the wrappers were
deliberately not used and point at `AB-PROTOCOL.md` §2 for why.

**§2 The task list and its answer keys**, one row per task: id, category, expected value, match
mode, and the derivation command from `MANIFEST.tsv`. A reader must be able to confirm the grading
was not fitted after the fact.

**§3 The raw per-cell table** — every row of `ab.tsv`, not a summary of it: task, arm, rep, verdict,
qualifier, extracted answer, `prompt_tokens`, `completion_tokens`, `finish_reason`, wall clock.
Include it in full even if it is long; the aggregate must be independently recomputable from this
table alone.

**§4 Per-arm aggregate, in four categories.** For each arm: correct / incorrect / **no-answer** /
**no-output**, as counts and as a percentage of that arm's cells, plus median and p90 wall clock,
plus median `prompt_tokens` and `completion_tokens`.
🔴 **Do not collapse `no-answer` or `no-output` into `incorrect`.** A thinking arm whose trace
consumed the fixed per-turn completion budget produced no answer; scoring that as a wrong answer
would report a budget artefact as a reasoning failure. If the thinking arm shows a materially higher
`no-output` rate, say so as its own finding, with the `finish_reason` evidence, and note that per
`AB-PROTOCOL.md` §3 the completion budget is a shared constraint neither arm can be given more of
through cline.

**§5 The prefix control.** Arm B (`flashnext-act`, `hosted_vllm/`, thinking off) against arm A
(`flashnext`, `openai/`, thinking off), at whatever replication it was run. State whether the
transformation path alone moved anything. Phase 10 predicted these two to be indistinguishable
(`phase-10/REACH-PROOF.md` §5, delta 0) — record agreement or disagreement, and note that B's lower
replication limits what its comparison can carry.

**§6 The descriptive statistic.** The two-sided permutation test over per-cell correctness (A vs C),
≥10,000 shuffles, with the observed gap and the p-value, and an explicit sentence that it is
descriptive and **not** the decision criterion.

**§7 Void-condition check.** Walk each condition from `AB-PROTOCOL.md` §5 and state whether it was
triggered: version drift mid-batch; >25% unparseable in either arm; any task exceeding the
prompt-token ceiling; runaway-agent exclusions. State the outcome of each check even when it is "not
triggered" — a check whose result is not written down did not happen.

**§8 The decision rule, applied.** Quote §5 of `AB-PROTOCOL.md` **verbatim**, then show the
arithmetic — arm C's correct count, arm A's correct count, the gap, the threshold — and state the
rule's mechanical output as one labelled line:
`RULE OUTPUT: keep` or `RULE OUTPUT: revert`.
Then, as its own paragraph, restate what would have produced the opposite output, and confirm it was
written before the data (cite the protocol's commit or timestamp).
**This document does not declare the decision.** Say so explicitly: the ratified decision and the
`DECISION:` line belong to plan 11-07, after human review, because it changes the default behaviour
of a shipped tool.

**§9 Limitations, stated plainly and not as a footnote.** At minimum: N and the resulting resolution
(what size of true effect this run could and could not have detected); temperature-1.0 sampling; a
task set built for this project rather than an external benchmark, with a pointer to
`AB-TASKSET.md` §1's set-aside decision; the shared completion budget; the single model, single
machine, single day; and anything the run itself surprised you with.

**§10 The `flashnext-reach-xhigh` note.** `phase-10/PHASE-10-FINDINGS.md` §5 left open whether that
verification-only alias should remain in the live config now that Phase 10's reach questions are
closed. It is not part of this A/B. Record that it is still present (or not) and that the decision is
handed to Phase 12, so it is not silently dropped a second time.
  </action>
