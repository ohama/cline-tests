<objective>
Build the two wrappers that make a mode/alias mismatch impossible, and prove they do it by reading
the argv they actually hand to the binary — not by reading their source.

Purpose: USE-01. Until 2026-09-02 this phase's premise was that `--thinking` did not exist, so a
wrapper only had to supply the right flags. That premise is now false: the installed `cline` 3.0.60
has `--thinking <level>`, and litellm's router spreads client kwargs *after* the alias's
`litellm_params` (`phase-10/ALIAS-DESIGN.md` §3), so a client-sent `reasoning_effort` **overrides**
whatever `flashnext-plan` injects. A wrapper that forwards `"$@"` — which is exactly what
`docs/plan-act-reasoning-design.md`'s L3 sketch does — lets any caller silently defeat the entire
alias mechanism by appending one flag. The wrapper's job is therefore not convenience; it is
refusal.

Output: `phase-11/wrapper.env`, `phase-11/wrapper_common.sh`, `phase-11/cline-plan`,
`phase-11/cline-act`, a stub-`cline` argv-capture harness, a behavioural test proven able to fail,
and `phase-11/WRAPPER-DESIGN.md`.

**Outcome neutrality:** this plan's deliverable is a wrapper whose real behaviour has been observed
and recorded. If some flag turns out to be impossible to block cleanly, or the deny-by-default
parser turns out to reject something a real user needs, that is a finding to write into
`WRAPPER-DESIGN.md` as a limitation — not a reason to loosen the test until it passes.
</objective>

  <action>
Create `phase-11/wrapper.env` — the one file that defines what the wrappers target. It is sourced,
never duplicated:

```sh
# phase-11/wrapper.env — the ONLY place the wrapper's target aliases are defined.
# USE-03 may revert cline-plan's alias to `flashnext` if the A/B shows no improvement
# (.planning/REQUIREMENTS.md USE-03). That revert must be a one-line change HERE,
# with a git diff as its audit trail — never an edit to wrapper logic.
WRAPPER_PLAN_ALIAS="flashnext-plan"
WRAPPER_ACT_ALIAS="flashnext-act"
WRAPPER_PROVIDER="openai-compatible"
WRAPPER_COMPACTION="agentic"
WRAPPER_DEFAULT_TIMEOUT="600"
# Absolute path. NEVER bare `cline`: a shell function, alias, or a same-named
# wrapper earlier on PATH would make this recurse into itself.
WRAPPER_CLINE_BIN="/opt/homebrew/bin/cline"
```

Create `phase-11/wrapper_common.sh` — sourced by both wrappers after they set `WRAPPER_SELF`,
`WRAPPER_MODE_FLAG` and `WRAPPER_ALIAS`. It holds the parser and the single construction site of the
real command, so the two wrappers cannot drift apart in their argument handling.

**Parsing is deny-by-default, not a blocklist.** Accept exactly four option forms and nothing else:
`-t|--timeout <secs>`, `-c|--cwd <path>`, `--json`, and `--` (end of options). Any other argument
beginning with `-` is refused with exit **2** and a message naming it. Deny-by-default is
deliberately stronger than the blocklist the research proposed: CFG-05 means the binary can gain a
new flag at any time without notice (`--thinking` and `-p` both appeared between 3.0.53 and 3.0.60
without anyone asking), and a blocklist written today would silently pass tomorrow's reasoning flag.
Record that reasoning in the script's header comment.

Four flags get a **specific** message rather than the generic one, because a user typing them has a
concrete wrong mental model worth correcting:

```
-m|--model      REFUSED: $WRAPPER_SELF does not accept '-m/--model'. The alias is fixed by
                phase-11/wrapper.env (currently: $WRAPPER_ALIAS) — that pairing is the whole
                point of this wrapper (USE-01).
-P|--provider   REFUSED: ... provider is fixed to $WRAPPER_PROVIDER.
--thinking*     REFUSED: $WRAPPER_SELF does not accept '--thinking'. Reasoning effort is injected
                server-side by the litellm alias. litellm merges client kwargs AFTER the alias's
                litellm_params (phase-10/ALIAS-DESIGN.md §3), so a client-sent reasoning_effort
                OVERRIDES the alias — using --thinking silently bypasses this wrapper's guarantee.
                See .planning/REQUIREMENTS.md CFG-11, 2026-09-02 correction.
-p|--plan       REFUSED: the mode flag is fixed by which wrapper you invoked.
```

Match `--thinking` in every form the CLI accepts: bare `--thinking`, `--thinking high`, and
`--thinking=high`. Use a `case` on `--thinking|--thinking=*` — a plain equality test misses the
`=` form, and that miss would be exactly the silent hole this plan exists to close.

**Reject, never strip.** Silently dropping a flag the user explicitly typed is the same
silent-success failure mode CFG-14 bans `drop_params` for and `phase-10/ALIAS-DESIGN.md` §4 names
again. The user must be told, and the binary must not run.

After option parsing, the remaining arguments are the prompt, joined with single spaces into one
argv element. Refuse (exit 2) if there are none, or if the joined prompt begins with `-` (it would
be re-parsed as a flag by the real binary) — with a message saying so.

**Construction site**, the only place the binary is named:

```sh
CMD="$WRAPPER_CLINE_BIN"
set -- -P "$WRAPPER_PROVIDER"
[ -n "$WRAPPER_MODE_FLAG" ] && set -- "$@" "$WRAPPER_MODE_FLAG"
set -- "$@" -m "$WRAPPER_ALIAS" --compaction "$WRAPPER_COMPACTION" -t "$TIMEOUT"
[ -n "$JSON_FLAG" ] && set -- "$@" --json
[ -n "$CWD" ] && set -- "$@" -c "$CWD"
set -- "$@" "$PROMPT"
CLINE_NO_AUTO_UPDATE=1 "$CMD" "$@"
```

`CLINE_NO_AUTO_UPDATE=1` is set for the same reason `phase-10/probe_vrf04_cline.sh` sets it: it is
not proven to work (CFG-05 is unresolved and the binary drifted 3.0.53→3.0.60 anyway) but a version
change mid-use would silently invalidate every pinned fact this wrapper rests on.

**Test hook, explicitly not a bypass.** `wrapper_common.sh` substitutes `$CLINE_WRAPPER_TEST_BIN`
for `$WRAPPER_CLINE_BIN` **only** when `CLINE_WRAPPER_TEST=1` is also set, and when it does so it
prints `[TEST MODE] using $CLINE_WRAPPER_TEST_BIN instead of $WRAPPER_CLINE_BIN` to stderr. Test
mode must never be silent — a silent override is a way for the real binary to be swapped without
anyone noticing.

**Config guard cycle** (the project's own standing pattern, `docs/headless-wrapper.md` §7), skipped
entirely when `CLINE_WRAPPER_TEST=1`:
- **Before** invoking: run `phase-01/config/verify_config.sh` with
  `VERIFY_CONFIG_NO_WRAPPER_CHECK=1` exported. On non-zero, print the failure and exit **3** without
  invoking anything, printing the exact `phase-01/config/apply_provider_config.sh` command the user
  can run. **Do not auto-heal** — a wrapper that silently rewrites `providers.json` is a hidden side
  effect, and healing is `phase-04/run_headless.sh`'s documented policy for its own unattended
  surface, not this interactive one.
- **After** the binary returns: run the same check again. On non-zero, print
  `WARNING[CONFIG]: cline exited <rc>, but the post-run config guard failed` and exit **4**. Do not
  swallow it into the child's exit code; do not hide it behind a warning that returns 0.
  <br>🔴 `VERIFY_CONFIG_NO_WRAPPER_CHECK=1` is what stops infinite recursion once plan 11-03 makes
  `verify_config.sh` itself exercise these wrappers. Write the variable and the reason into the
  script now, even though nothing reads it yet — 11-03 depends on it existing.

Exit-code contract (document it in the header of every one of these three files):
`0..N` = the real cline's own exit code; `2` = refused argument or usage error, nothing invoked;
`3` = pre-run config guard failed, nothing invoked; `4` = post-run config guard failed.

Then `phase-11/cline-plan`:

```sh
#!/usr/bin/env bash
set -euo pipefail
HERE="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
. "$HERE/wrapper.env"
WRAPPER_SELF="cline-plan"
WRAPPER_MODE_FLAG="-p"          # ROADMAP Phase 11 criterion 1: always -p -m <plan alias>
WRAPPER_ALIAS="$WRAPPER_PLAN_ALIAS"
. "$HERE/wrapper_common.sh"
```

and `phase-11/cline-act` identically but with `WRAPPER_SELF="cline-act"`, `WRAPPER_MODE_FLAG=""`
(empty — Act mode is the CLI's default and passing no mode flag is what "act" means), and
`WRAPPER_ALIAS="$WRAPPER_ACT_ALIAS"`.

`chmod +x` all three of `cline-plan`, `cline-act`, and (in Task 2) `testing/stub-cline`.

Positive cases — the wrapper must invoke the stub and the captured argv must satisfy:
- `P1 cline-plan "hello"` → contains `-p`; contains `-m` immediately followed by the value of
  `WRAPPER_PLAN_ALIAS` read from `wrapper.env`; contains `-P openai-compatible`; contains
  `--compaction agentic`; the last argument is exactly `hello`; `-m` appears **exactly once**;
  `--thinking` appears **zero** times; `CLINE_NO_AUTO_UPDATE=1` recorded.
- `P2 cline-act "hello"` → contains `-m` + `WRAPPER_ACT_ALIAS`; contains **neither** `-p` nor

- `P3 cline-plan --timeout 90 --json "hello"` → contains `-t 90` and `--json`.
- `P4 cline-plan -- "-weird prompt"` → refused with exit 2 (prompt begins with `-`), stub NOT
  invoked. Record it as a documented limitation rather than a bug.

Refusal cases — the wrapper must exit non-zero **and the stub must not have been invoked at all**
(assert by byte-comparing the argv file before and after; "the flag didn't reach the binary" is only
provable if nothing reached the binary):
- `R1 cline-plan --thinking high "x"` → exit 2, message contains `--thinking`

- `R3 cline-plan --thinking "x"` → exit 2 (bare form; note the CLI's own bare `--thinking` means

- `R4 cline-act --thinking high "x"` → exit 2
- `R5 cline-plan -m flashnext "x"` → exit 2, message contains `-m`
- `R6 cline-act -m flashnext-codex "x"` → exit 2. Call this out in the row's note: the codex alias

- `R7 cline-plan -P openai "x"` → exit 2
- `R8 cline-act -p "x"` → exit 2
- `R9 cline-plan --auto-approve false "x"` → exit 2 (generic refusal — proves deny-by-default, not

Short document, the authoritative source Phase 12's USE-04 will write the manual from. Cover:

1. **The contract.** Usage line for each wrapper, the four accepted option forms, the exit-code
   table (0..N / 2 / 3 / 4), and the constructed command line verbatim for each wrapper, quoted from
   an actual captured `argv.tsv` row rather than retyped.
2. **Why scripts, not the design doc's shell functions.** `docs/plan-act-reasoning-design.md` §L3
   and `-implementation.md` §T5 both sketch `cline-plan() { ... cline -p -m flashnext-plan "$@"; }`.
   Three problems, stated plainly: (a) `"$@"` is Pitfall 2 — it forwards `--thinking high` and a
   second `-m` straight through; (b) a shell function cannot be statically inspected by
   `verify_config.sh`, which USE-02 requires; (c) a function cannot be invoked by path from another
   process, so the stub-argv harness and the A/B could not exercise it. Note that Phase 12 owns
   updating those two design documents (USE-05).
3. **Why deny-by-default rather than a blocklist**, with the CFG-05 drift argument: `--thinking` and
   `-p` both appeared between 3.0.53 and 3.0.60 unannounced, so any list of forbidden flags written
   today is a list that will be incomplete tomorrow.
4. **Why reject rather than strip**, citing CFG-14 and `phase-10/ALIAS-DESIGN.md` §4: converting an
   explicit user instruction into a silent no-op is the failure shape this project has been bitten
   by twice.
5. **What `-p` actually does, and what it does not.** Per `11-RESEARCH.md` Q2: `-p` sets Cline's own
   agent mode (tool availability — Plan mode gets only `switchToActModeTool`), which is orthogonal
   to the model alias and to reasoning. `-m <alias>` alone selects the injected parameters; no `-p`
   is required for reasoning to reach the model (`phase-10/PHASE-10-FINDINGS.md` §5). The wrappers
   pair them because ROADMAP criterion 1 says so, as a deliberate product decision — **not because
   the reasoning injection needs it.** State this explicitly, because it is the reason the USE-03
   A/B must be run without `-p` (holding tool availability constant across arms) even though the
   shipped wrapper sets it.
6. **The single-source alias and the USE-03 revert path.** `wrapper.env` is the only place;
   the revert, if USE-03's A/B calls for it, is one line there and nothing else.
7. **Limitations, honestly.** At minimum: prompts beginning with `-` are refused (case P4);
   `--auto-approve`, `--hooks-dir`, `--id`, `-s/--system` and every other real cline flag are
   unreachable through these wrappers by design, so a user who needs one must call `cline` directly
   and thereby lose the pairing guarantee; the config guard aborts rather than heals; and test mode
   exists (`CLINE_WRAPPER_TEST=1`) and is loud but is nevertheless a way to point the wrapper at a
   different binary.
8. **The interaction plan 11-03 will have to solve**, recorded here so it is not rediscovered:
   `verify_config.sh` is about to exercise these wrappers, and these wrappers call
   `verify_config.sh`. `CLINE_WRAPPER_TEST=1` (wrapper skips its guard) plus
   `VERIFY_CONFIG_NO_WRAPPER_CHECK=1` (verify_config skips the wrapper section) are the two brakes;
   11-03 must prove there is no recursion rather than assume it.
