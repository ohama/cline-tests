        Tailscale re-login. Point at `phase-06/IPAD-CHECKLIST.md`.
     b. NET-05's Telegram half. State the static finding (one non-repeating typing call site,
        Telegram decays typing after ~5s, no resend loop, streaming only starts once output
        tokens exist) and the outcome of the 06-05 decision, whatever it was. If the trial was
        declined, say the question is open. If it was run, quote the user's observation as
        theirs.
     c. NET-02's interpretation, stated plainly and not smuggled: the requirement says a LAN
        device must not reach kanban without a token. What was built is stronger and simpler —
        **there is no LAN path at all**, so no token exists to discuss. Explain why that
        satisfies the requirement's intent, and note that a genuine LAN+passcode path remains
        possible later as a separate, explicit decision (kanban ships that mechanism), not as
        a side effect.
     d. NET-04's mechanism, stated plainly: the guarantee is that OUR launchd-supervised
        service refuses to start without a numeric allowlist id. The cline binary itself still
        starts happily without the flag — verified live. The requirement's intent is met; the
        literal mechanism differs. Name the enforcement point by file.

     Both are read-only and re-runnable.
