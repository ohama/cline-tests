<house_rules_for_this_phase>
These bind every plan in Phase 6. Re-read them at the start of each plan.

1. NEVER run the Tailscale public-internet subcommand (the one whose name begins with
   "fun"). Only `tailscale serve`. Every plan asserts afterwards that no NEW public
   entry appeared.
2. Kanban's bind NEVER changes. It stays `--host 127.0.0.1 --port 3484`. If a task finds
   itself editing kanban's host flag, it has taken a wrong turn — stop and report.
   The string `0.0.0.0` must not appear anywhere under `phase-05/` or `phase-06/`.
3. Port 3000 stays unbound. Reason: this Mac already has a pre-existing, live public
   Tailscale entry on `:8443` forwarding to `http://127.0.0.1:3000`. Anything that binds
   3000 becomes world-reachable with no Tailscale login. Not hypothetical — verified live.
4. `phase-02/infra/restart_service.sh <label> <port|none>` is the ONLY sanctioned restart
   path. Never `kill`/`pkill`/`launchctl load|unload|kickstart`. Back up and `plutil -lint`
   before any plist change. Never LEAVE a crash-looping service.
5. `EXTRA_ALLOW_PATHS` stays EMPTY. Do not disturb pids 46573 (flashnext), 75548
   (role-shim), 48525 (litellm), 53894 (kanban), 56669 (telegram-connect) except through
   `restart_service.sh` where a plan explicitly says so.
6. macOS `/bin/bash` is 3.2 — indexed arrays only, no `declare -A`. The executing shell is
   zsh: wrap any space-separated-variable word-splitting in `bash -c '...'`.
7. EVERY `tailscale` invocation prints
   `Warning: client version ... != tailscaled server version ...` to stderr. This is
   pre-existing and benign. Filter it (`grep -v '^Warning: client version'`) and never
   gate success on stderr being empty.
8. WORDING-COLLISION TRAP (has bitten this project ~10 times): explanatory prose inside a
   file can collide with that same file's own verification greps. Before committing any
   file, run the plan's own greps against it. In particular, no file under `phase-06/net/`
   may contain the Tailscale public-internet subcommand name adjacent to `tailscale` —
   describe it as "the public-exposure mode" instead.
9. `cline` invocation budget for the WHOLE phase: 2. After ANY `cline` invocation run
   `bash phase-01/config/verify_config.sh`; if it fails, heal with
   `bash phase-01/config/apply_provider_config.sh` and re-verify. This plan spends 0.
</house_rules_for_this_phase>
