<objective>
Build the missing link 06-04 discovered, and prove it entirely over loopback. The network
stays closed for the whole of this plan.

Purpose: 06-04 proved the Serve mechanics are correct and then hit kanban's own defense —
`getAllowedHostHeaders()` in the installed `dist/cli.js` hardcodes `{localhost:<port>,
127.0.0.1:<port>}` whenever kanban is loopback-bound, with no flag or env var to widen it.

that rewrites the Host header. This plan authors that process, registers it as a supervised
service, extends the standing gate to cover it, and proves every behaviour against the live
kanban over loopback — so that 06-04.2 opens the network exactly once, already knowing it
works.

**D. Write `phase-06/net/kanban_host_proxy.js`.** Node builtins ONLY (`http`, `net`, `url`) —
no `npm install`, no `http-proxy`, nothing added to any package manifest. Node is chosen over
python3 deliberately and the reason goes in the file header: node is already a hard dependency
of kanban itself (`/opt/homebrew/bin/kanban` is a `#!/usr/bin/env node` script and both Phase 5
plists already pin `/opt/homebrew/bin` on PATH for exactly that reason), and node's `http`
module surfaces `upgrade` as a first-class event with the raw socket, so the WebSocket path is
a documented pipe rather than hand-rolled HTTP framing. python3's stdlib has no equivalent —
`http.server` cannot express a protocol upgrade at all, so the python route would mean
hand-parsing HTTP inside a security-relevant component. Neither adds a dependency; node is the
one that does not require inventing a parser.

Behaviour, exactly:

1. Read every setting from `process.env` (the wrapper exports them from config.env). Refuse to
   start — non-zero exit with a clear message — if any is missing or if the listen host is not
   the literal `127.0.0.1`.
2. `server.listen(PROXY_PORT, '127.0.0.1')`. **The host argument is mandatory and must be
   passed**: node's `listen(port)` with the host omitted binds every interface, which would
   silently create a LAN path and break NET-02. Say that in a comment (without writing the
   wildcard literal).
3. A shared `gate(headers)` helper used by BOTH the request path and the upgrade path:
   - no `host` header, or `host.toLowerCase()` not in `PROXY_ALLOWED_HOSTS` -> reject.
   - `origin` present and not in `PROXY_ALLOWED_ORIGINS` -> reject.
   - Rejection on the request path: `403` + `{"error":"Host not allowed."}` /
     `{"error":"Origin not allowed."}`, `Content-Type: application/json; charset=utf-8`,
     `Cache-Control: no-store` — deliberately byte-compatible with kanban's own `rejectRequest`
     so a rejection reads identically wherever it came from. Rejection on the upgrade path:
     write `HTTP/1.1 403 Forbidden\r\nConnection: close\r\n\r\n` and destroy the socket, the
     same shape as kanban's `rejectSocket`. **A rejected request is never forwarded upstream.**
4. On a request that passes the gate: copy the headers, set `host` to
   `PROXY_UPSTREAM_HOST_HEADER`, and if an `origin` was present set it to
   `PROXY_UPSTREAM_ORIGIN`; forward to `127.0.0.1:3484` with `http.request`, preserving method,
   path and body (pipe, do not buffer). Stream the response back with its status and headers.
   If the response carries `access-control-allow-origin` equal to `PROXY_UPSTREAM_ORIGIN` and
   we rewrote an inbound Origin, restore that header to the inbound Origin value.
5. On `upgrade`: run the same gate, rewrite the same two headers, open a `net.connect` to
   `127.0.0.1:3484`, replay the request line and rewritten headers verbatim, write any
   `head` bytes node already read, then `pipe()` both directions. Destroy both sockets on
   either side's `error` or `close`. This is what makes live card updates work — kanban's UI
   opens `/api/runtime/ws`, `/api/terminal/io` and `/api/terminal/control` as WebSockets
   (confirmed by reading the shipped bundle `dist/web-ui/assets/index-*.js`, which builds them
   from `window.location.host`), so a proxy that handled only plain HTTP would serve the first
   page perfectly and then be silently dead.
6. `server.on('clientError', (err, socket) => socket.destroy())`. Do not add any
   `X-Forwarded-*` header — kanban ignores them and adding nothing keeps behaviour identical to
   a direct loopback call.
7. Log one line to stdout on listen (`host:port` and the upstream), and one line per rejection
   (method, path, the offending Host/Origin) — never log request bodies or cookies.

**Security note that must appear in the file header and be repeated in the results README:**
the proxy does not delete kanban's defense, it translates it. kanban rejects a non-loopback
Host to stop DNS-rebinding and cross-site attacks against a localhost server. The proxy keeps
exactly that shape by maintaining its own four-entry Host allowlist and three-entry Origin
allowlist and rejecting anything else itself; the only origin it ever launders into the
upstream-allowed value is `https://<tailnet name>:8444`, which is the app's own origin. It
therefore never becomes a way to reach kanban with an arbitrary Host or Origin, and because it
binds loopback only it is not a second way into this machine at all — the only thing that can
reach it is `tailscale serve`, itself connecting from loopback on behalf of an authenticated
tailnet peer.
