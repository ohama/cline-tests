Content, all of it required:

**What they are and how you invoke them.** `phase-11/cline-plan` and `phase-11/cline-act` are shell
scripts wrapping the real `cline` binary. **Neither is installed on `$PATH` or symlinked anywhere** —
invoke by explicit path. `cline-plan` runs plan mode and always emits `-p -m flashnext-plan`;
`cline-act` runs act mode and always emits `-m flashnext-act` with no `-p`. The mode and the alias are
paired at a single construction site and cannot be set independently — that pairing is the entire
point of the wrappers.

**Accepted arguments — a whitelist, not a blocklist.** Exactly four options pass: `-t`/`--timeout`,
`-c`/`--cwd`, `--json`, and `--`. **Every other argument beginning with `-` is refused by name on
stderr, with exit 2, before the real binary is ever invoked.** Say explicitly that this is
deny-by-default: the wrapper refuses unknown flags it has never heard of, which is the structural
defence against a future cline release adding a flag unannounced (CFG-05 makes that a live risk).
Name the four that get specific refusal reasons — `-m`, `-P`, `--thinking`, `-p` — and quote the
refusal message verbatim from `phase-11/wrapper_common.sh` rather than paraphrasing it, so a user
who hits it can match the text.

**Exit codes — a table.** This is the part users get wrong:
- `0..N` — cline's own exit code, forwarded unchanged.
- `2` — refused argument. **The binary was never invoked.**
- `3` — pre-run config guard failed, or the `providers.json` scratch-copy containment could not be
  established. **The binary was never invoked.**
- `4` — post-run config guard failed. **cline itself may well have exited 0 and answered correctly**;
  this code means the configuration drifted, and the response to it is to re-run
  `apply_provider_config.sh`, not to assume the task failed.

**The `providers.json` containment — state it precisely.** Every `cline -m` call rewrites
`~/.cline/data/settings/providers.json`'s `model` field; this is unconditional in cline's own startup
path and has been since at least 3.0.53. Measured at 31/31, 100%, during Phase 11's A/B. The wrappers
**contain** it: each call copies the real file to a per-invocation `mktemp`, points
`CLINE_PROVIDER_SETTINGS_PATH` at the copy, and traps `EXIT`/`INT`/`TERM` to remove it, so the write
lands on the scratch copy and the shared file Kanban and Telegram also read is untouched. If the
scratch copy cannot be created the wrapper refuses with exit 3 rather than running uncontained.

**Write "contained", never "fixed" or "resolved".** The underlying write is not eliminated at the
source; a bare `cline -m` invocation outside the wrapper still mutates the shared file. State that
the containment is one day old (commit `017c65e`, 2026-09-10) with no production track record.

**What the wrappers deliberately do not do** — copy `phase-11/WRAPPER-DESIGN.md` §7's honest
limitations rather than claiming misuse is impossible: prompts beginning with a dash are refused
outright; roughly fifteen real `cline` flags are unreachable through the wrapper by design; the
config guard **aborts** rather than heals. The accurate claim is that the wrappers refuse a wide,
extensible class of dangerous arguments and contain the one side effect they cannot prevent at
source — not that they make misuse impossible.

**Which alias `cline-plan` targets, and why.** It targets `flashnext-plan`
(`enable_thinking:true` + `reasoning_effort:medium`), and it was **kept, not reverted**. State the
reason honestly and in the manual's own plain register: the A/B found **no accuracy difference**
(both arms 25/30 on the tasks both attempted at equal replication; permutation test p=0.563), the
pre-registered rule's output was therefore `revert`, and a human **overrode** it to `keep` because
the `providers.json` side effect had just become containable — a safety reason, not a quality one.
Cite `phase-11/AB-RESULTS.md` §11. `phase-12/verify_docs.sh` requires `25/30`, `p=0.563`, `override`
and that citation to appear wherever the A/B is mentioned; no reader may come away believing the A/B
favoured `flashnext-plan`.

**Cross-references, not duplication.** Point at §8 (GAP-CLINE-VERSION) for how to check the real
cline version rather than repeating the instructions; point at `docs/cline-config-pins.md` for the
alias parameter pins; point at `phase-11/WRAPPER-DESIGN.md` for the full contract. Every path you
cite must exist — the sweep `test -e`s them.
