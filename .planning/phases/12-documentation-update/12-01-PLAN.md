<objective>
Build the grader before the work is graded.

This phase's signature failure mode is declaring a document updated while the false sentence is
still in it — this project has already done exactly that once in miniature (`qanda/004` §5 kept
calling the containment "a proposal" for hours after it shipped, while three other documents cited
it as evidence). The defence is a checker that names, per file, the exact strings that must be gone
and the exact anchors that must be present, written **now**, before any editor sees a document — so
the assertions cannot be quietly retro-fitted to whatever the editors happened to write.

This plan writes that checker, proves it can fail (seeded mutants, the `phase-11/selftest_verify_wrappers.sh`
pattern), captures its RED baseline against today's uncorrected docs, and records the phase's scope
decisions.

Purpose: every wave-2 plan gets an unambiguous, mechanical definition of "done" that it did not
author.
Output: `phase-12/verify_docs.sh`, `phase-12/selftest_verify_docs.sh`, `phase-12/SCOPE-DECISIONS.md`,
and a captured RED run.
</objective>

<task type="auto">
  <name>Task 2: Write the documentation sweep, phase-12/verify_docs.sh</name>
  <files>phase-12/verify_docs.sh</files>
  <action>
Write `phase-12/verify_docs.sh`, following the house idiom of `phase-11/verify_wrappers.sh`
literally: a header comment explaining why the file exists and what it deliberately does not do;
`set -uo pipefail` **without** `-e` (an aborting checker under-reports — the same reason
`phase-11/verify_wrappers.sh` and `phase-11/wrapper_argv_test.sh` make this choice); `fail()` /
`ok()` helpers printing `FAIL[DOCS]: ...` to stderr and `OK[DOCS]: ...` to stdout; a `FAIL_COUNT`;
and **exit 5** on any failure — a code distinct from `verify_config.sh`'s providers.json exit 1 and
`verify_wrappers.sh`'s exit 3, so a caller can always tell the three faults apart by exit code alone.
Exit 0 only when every assertion passed.

`DOCS_ROOT="${DOCS_ROOT:-<repo root>}"` — default to the real repository (derived from the script's
own location, `$SCRIPT_DIR/..`), overridable to point at a fixture tree. This is the one variable
Task 3's selftest changes, exactly as `WRAPPER_DIR` is in `verify_wrappers.sh`.

**bash 3.2 — no `declare -A`.** Carry the assertion tables as newline-delimited `TAB`-separated
records in a heredoc-fed `while read` loop, or as parallel indexed arrays. Do not use associative
arrays.

**Absence is a failure, not a skip.** If a target document is missing from `DOCS_ROOT`, that is a
`FAIL[DOCS]`, reported before any of its own assertions run. A "file not present, skipping" branch
returning 0 would be exactly the instrument-that-observes-nothing pattern
`phase-10/PHASE-10-FINDINGS.md` §4.6 catalogues.

**Live body vs preserved appendix — the central mechanic.** These corrections follow
`docs/32k-compaction-policy.md`'s precedent: the pre-correction text is *preserved verbatim in a
collapsed appendix*, never deleted. So a naive whole-file grep for a false string would fail
forever. Define:

- `live_body <file>` — everything **above** the first line matching the literal
  `부록 — 정정 전 기록`. If no such line exists, the live body is the whole file.
- `appendix <file>` — everything from that line onward (empty if absent).

Forbidden-literal checks run against `live_body` only. Then the inverse check, which is the point:

- **APPENDIX_INTEGRITY** — for a file configured as `appendix_required`, assert (a) the
  `부록 — 정정 전 기록` marker exists, and (b) **every** forbidden literal for that file is still
  found in the `appendix`. A correction that deleted the original instead of preserving it fails
  here. This makes "nothing deleted, only superseded" mechanically enforced, not a hope.

**Prior art, and the one hazard it warns about — read before writing the FORBIDDEN class.**
v1 already built two things here and this sweep is the synthesis of both:

- `phase-07/results/20260831T023128Z-close/anti-overclaim.md` — the "8/8" sweep the milestone record
  cites. It is a **hand-written, sentence-cited Markdown document**, not an executable: for each of
  eight named claims it quotes the sentence that satisfies it with a `file:line`. Its plan
  (`.planning/milestones/v1-phases/07-cline-bench-verification/07-16-PLAN.md` Task 3) states the
  rule this phase inherits verbatim: *"A FAIL is fixed, not annotated."*
- `phase-08/manual/check_manual_claims.sh` — the executable manual gate (exit 0 / 1 / 2, a
  `--negative-control` mode that inverts the expectation against a deliberately broken fixture
  corpus, and a `CASES $passed/$total` tally). **Its header explicitly refuses forbidden-string
  checks**, and the reason is a real hazard this sweep must handle rather than rediscover:

  > a forbidden-literal grep collides with prose that legitimately names the thing it forbids
  > (this project's own `docs/cline-bench.md` §9 has to spell out its own forbidden sentences in
  > order to forbid them — a naive grep over that section would trip on the section that is doing
  > the forbidding).

  That gate's answer was to check only that required honesty markers are *present*.

This sweep does **both**, because presence-only checking cannot catch this phase's actual failure
mode (a false sentence left in place beside a correct new one). Three mitigations make the
forbidden class safe:

- **The appendix split** (below) — the preserved original lives outside the searched region.
- **Correction tables paraphrase, they do not quote.** `docs/32k-compaction-policy.md` §7's own
  "이 정정이 바꾸는 것" table is the model: its 이전 column reads `models[].contextWindow: 32768`
  and `400 을 종료 조건으로 처리` — short paraphrases, never the verbatim superseded sentence. Every
  forbidden literal in the table below is a long, distinctive full sentence that no such paraphrase
  reproduces. Wave-2 plans are instructed to follow that shape.
- **An auditable escape hatch.** A line carrying the trailing marker `<!-- verify_docs:allow -->` is
  excluded from forbidden-literal matching — for the genuine case where a document must name a false
  sentence in order to disown it. The sweep **counts every use of the escape and prints the count and
  the file:line of each in its summary**. An escape that silently neutralised a check would recreate
  the exact defect this sweep exists to catch; making each one visible in the transcript means a
  reviewer sees it. Zero uses is the expected state.

**Assertion classes.** Implement all six:

1. `FORBIDDEN <file> <exact substring>` — must NOT appear in the file's live body, escape-marked
   lines excluded. Use exact substring matching (`grep -qF --`, the house idiom), never a fuzzy
   regex — a regex over Korean prose produces false positives on correct sentences and would train
   the reader to ignore this checker.
2. `REQUIRED <file> <exact substring>` — must appear anywhere in the file.
3. `REQUIRED_ANY <file> <label> <substring>|<substring>|...` — at least one alternative must
   appear. Use this wherever the true claim can be phrased more than one way; it keeps the checker
   from dictating prose.
4. `CITED_PATHS_EXIST <file>` — extract every backtick-delimited token in the live body that starts
   with `docs/`, `howto/`, `qanda/`, `phase-` or `.planning/`, strip any trailing `:<line>` or
   `#<anchor>` suffix and any trailing punctuation, and `test -e` each against the repo root. Report
   each miss by name. (This is the `test -e` habit `phase-11/PHASE-11-FINDINGS.md` §2/§3 already
   uses on its own evidence paths.) Skip tokens containing `~`, a leading `/`, or a space.
5. `TAG_CITATION <file>` — if the live body contains `cli-v3.0.53`, it must also contain the literal
   `git show cli-v3.0.53:`. (Scope decision 6.)
6. `AB_DISCLOSURE <file>` — **conditional, and deliberately outcome-neutral.** If and only if the
   live body mentions the A/B at all (matches `A/B` or `AB-RESULTS`), it must contain *all* of:
   the literal `p=0.563`, the literal `25/30`, a `REQUIRED_ANY` over `override|오버라이드|뒤집`,
   and the literal `phase-11/AB-RESULTS.md`. This check does not prescribe a single sentence and
   does not favour a framing in either direction — it requires that wherever the A/B is discussed,
   the two disqualifying figures and the fact that the shipped decision overrode the rule's output
   travel with it, so no reader can come away believing the A/B favoured `flashnext-plan`. A
   document that does not discuss the A/B is not forced to.

beside it — a future reader must be able to tell why a string is forbidden without opening the
research document.
