<objective>
Build the re-runnable regression test itself: deterministic filler files, the prompt that makes Cline
grow its own conversation past 26.5k through its own tool-call loop, and the runner that captures both
oracles and hands them to the classifier.

Purpose: VER-01 (a re-runnable multi-turn test that pushes past 26,214 tokens) and the capture half of
VER-02. Research proved the design empirically: `cline --id <session>` resume is broken in 3.0.53
(100% failure across 5+ argument forms), so growth must happen inside ONE `cline --json` invocation by
asking the agent to `read_files` pre-staged filler files one at a time. Measured growth: ~2,300 tokens
per 8.8 KB properly line-wrapped file; a pathologically single-line file of the same size contributes
only ~650 tokens because Cline's tool-output limiter truncates it.

Output: `gen_filler.py`, `growth_prompt.txt`, `run_regression.sh`, and an offline dry-run test that
proves the plumbing before anyone spends 5-8 minutes of live model time.
</objective>

  <name>Task 1: Generate deterministic, properly wrapped filler files</name>
  <files>phase-01/filler/gen_filler.py, phase-01/prompts/growth_prompt.txt</files>
  <action>
Create `phase-01/filler/gen_filler.py` (stdlib only: `random`, `textwrap`, `pathlib`, `argparse`).

Requirements, driven directly by RESEARCH.md Pitfall 3:
- `--count N` (default 12) and `--outdir` (default `phase-01/filler`), `--seed` (default 20260829) so
  output is byte-identical across runs — the test must be re-runnable, not merely re-executable.
- Writes `wrapped_01.txt` .. `wrapped_NN.txt`, each ≈8.8 KB (target 8,500–9,200 bytes).
- Content must be realistically line-wrapped: ~100 characters per line, ~120 lines, wrapped at word
  boundaries via `textwrap.fill(width=100)`. NO line may exceed 120 characters. A single-long-line file
  hits Cline's tool-output limiter, gets `[line truncated]`, and contributes only ~650 tokens instead of
  ~2,300 — which silently breaks the growth math.
- Content should be plausible prose/pseudo-technical filler (a seeded shuffle of a word list is fine).
  Each file must begin with a line naming itself (e.g. `FILLER FILE 03 - seed 20260829`) so the NDJSON
  transcript is auditable.
- Print a summary table: file, bytes, line count, max line length, estimated token contribution
  (bytes / 3.8, labelled as an estimate).

Then create `phase-01/prompts/growth_prompt.txt` — the prompt that drives the tool loop. Base it on the
verified template from RESEARCH.md Pattern 1, with absolute paths substituted by the runner at run time
via a `{{FILE_LIST}}` placeholder:

```
Read the following files ONE AT A TIME using the read_file tool, in the order given, as separate
tool calls (never in parallel, never batched):
{{FILE_LIST}}
After reading each file, reply with exactly one acknowledgement word ("ok") and nothing else, then
read the next file. Do not summarise, do not analyse, do not quote the contents.
When every file has been read, reply with exactly: DONE
```
Keeping replies to one word matters: at 17 tok/s and 64 s TTFT, growing context by generating text
instead of by reading files makes the run ~20 minutes instead of 5-8.
  </action>

   # -c sets the agent's WORKING DIRECTORY (verified from `cline --help` on 3.0.53:
   #   "-c, --cwd <path>  Working directory"). It is NOT the config-directory flag — those are
   #   `--config <path>` and `--data-dir <path>`, and we deliberately do NOT pass either: this test
   #   must run against the REAL ~/.cline config, because CFG-01/CFG-02 are precisely the claim that
   #   the real providers.json takes effect.
   # Why point cwd at the filler dir: it makes the run's workspace a fixed, deterministic set of 12
   #   byte-identical generated files instead of the whole repo, whose contents grow with every results

10. Slice the server log: `tail -c +$((LOG_OFFSET+1)) "$FLASHNEXT_ERR_LOG" > "$RESULTS_DIR/flashnext_window.log"`.

11. Re-run `verify_config.sh` post-run and append the result to `$RESULTS_DIR/config_post_run.txt`
