<objective>
Pin the moving parts: freeze `cline` at 3.0.53 and `kanban` at 0.1.70, make `CLINE_NO_AUTO_UPDATE=1`
structurally impossible to forget, and stop relying on the `--compaction` default by passing the mode
explicitly.

Purpose: CFG-04, CFG-05, CFG-06. Cline background-updates itself on invocation — drift from 3.0.53 to
3.0.60 was reproduced twice during research, and every decompiled constant this phase depends on
(`CONTEXT_WINDOW_INPUT_RATIO`, `COMPACTION_TRIGGER_RATIO`, the notice event shape) is valid only for
3.0.53. Research also confirmed `--compaction` defaults to `{enabled:true, strategy:"agentic"}`; pinning
it explicitly is still required so a future default change cannot silently disarm the exact mechanism
this phase is measuring.

Output: one canonical env file every other script in this repo (and every plist in Phase 5) sources, a
drift-check script, and a short doc recording the pins with their evidence.
</objective>

Contents (with a one-line `#` comment above each explaining WHY, since these values are load-bearing):

```sh
# Cline silently background-updates itself on invocation; 3.0.53 -> 3.0.60 drift was reproduced
# twice during Phase 1 research. Every decompiled constant this project relies on is 3.0.53-specific.
export CLINE_NO_AUTO_UPDATE=1

# Pinned versions. check_versions.sh asserts these; Phase 5 plists must not float off them.
export CLINE_PINNED_VERSION=3.0.53
export KANBAN_PINNED_VERSION=0.1.70

export CLINE_BIN=/opt/homebrew/bin/cline
export KANBAN_BIN=/opt/homebrew/bin/kanban

# Provider/model pin. -m flashnext makes the flashnext-codex alias unreachable from any invocation;
# calling the codex alias killed mlx_vlm.server during research (29s outage, launchd restarted it).
export CLINE_PROVIDER=openai-compatible
export CLINE_MODEL=flashnext

# CFG-04: compaction mode is pinned explicitly. CONFIRMED from `cline --help` on the installed 3.0.53:
#   `--compaction <mode>   Context compaction mode: agentic|basic|off (default: agentic)`
# which agrees with the decompiled parser (no flag => {enabled:true, strategy:"agentic"}). The default
# is verified, not assumed — and still must not be relied on, because a default can move between
# versions while a pinned flag cannot.
export CLINE_COMPACTION_MODE=agentic

# The decompiled 3.0.53 trigger: effectiveMaxInputTokens = contextWindow*0.9; trigger = that*0.9.
# 0.81 is the composite ratio. Consumers MUST derive the trigger from the contextWindow actually in
# providers.json (`int(cw * CLINE_COMPACTION_TRIGGER_RATIO)`) rather than reusing the literal below:
# Plan 05 Branch B2 may lower contextWindow as a max_tokens mitigation, and a stale 26542 would make
# every downstream budget gate and below_trigger judgement wrong.
export CLINE_COMPACTION_TRIGGER_RATIO=0.81

# Default value at contextWindow=32768. CROSS-CHECK ONLY, not the authority: run_regression.sh derives
# the effective trigger from live config and overrides this, and phase-01/config/observed.env (Plan 05,
# sourced afterwards) republishes it for the configuration actually applied.
# PREDICTED ONLY — Plan 06 measures whether compaction actually fires.
export CLINE_PREDICTED_TRIGGER_TOKENS=26542
export CLINE_SERVER_MAX_KV_SIZE=32768

# Server-side oracle. Application logging goes to stderr; flashnext.log is a near-empty uvicorn
# access log and must NOT be used as the token oracle.
export FLASHNEXT_ERR_LOG="$HOME/llm-system/services/logs/flashnext.err"
```

Also define a helper the other scripts use to build the flag list, as a bash array assignment guarded
for POSIX sourcing, or simply as a documented string:
```sh
# Flags every headless run must carry. --auto-approve true is required for unattended tool loops.
# CONFIRMED from `cline --help` on 3.0.53: `--auto-approve <boolean>  Set tool auto-approval for all
# tools (default: true)`. It is the default AND we pass it explicitly at each call site, same reasoning
# as --compaction. Phase 4's shipped wrapper will use false per HLS-02 — a different surface, not this one.
# Not included here and deliberately never passed by Phase 1: `--config <path>` (configuration
# directory, default ~/.cline) and `--data-dir <path>` (isolated local state, default ~/.cline/data).
# Phase 1's whole claim is that the REAL providers.json takes effect, so config must NOT be isolated.
# `-c/--cwd <path>` is the agent's WORKING directory — unrelated to config; run_regression.sh sets it
# per-invocation for run-to-run determinism.
export CLINE_COMMON_FLAGS="-P ${CLINE_PROVIDER} -m ${CLINE_MODEL} --compaction ${CLINE_COMPACTION_MODE}"
```

`phase-01/config/cline-invocation.env` and performs three checks, printing `OK:`/`FAIL:` lines and
exiting non-zero if any fail.

Check A — version pins (CFG-05, CFG-06):
- `"$CLINE_BIN" --version` must equal `$CLINE_PINNED_VERSION` (3.0.53).
- `"$KANBAN_BIN" --version` must equal `$KANBAN_PINNED_VERSION` (0.1.70).
- Cross-check the installed package manifests too, since the binary and the npm package can disagree:
  `grep -m1 '"version"' /opt/homebrew/lib/node_modules/cline/package.json` and the same for
  `/opt/homebrew/lib/node_modules/kanban/package.json`.

Check B — no drift across invocations (the actual CFG-05 claim):
- Run `"$CLINE_BIN" --version` a first time, then run one more real cline invocation
  (`"$CLINE_BIN" config --json >/dev/null`), then run `--version` again, and assert all reported
  versions are still `$CLINE_PINNED_VERSION`. Same pattern for kanban using `--version` twice.
- Do NOT use `cline auth` or anything that writes providers.json here (Plan 01 owns that file).

Check C — plist environment (CFG-05 for launchd surfaces):
- Enumerate `$HOME/Library/LaunchAgents/*.plist`.
- For each, convert with `plutil -convert json -o - "$f"` and parse with `python3` (stdlib json).
- Select plists that reference cline or kanban: any element of `ProgramArguments` (or the
  `Program` string) containing `cline` or `kanban`, case-insensitive.
- For each selected plist, assert `EnvironmentVariables.CLINE_NO_AUTO_UPDATE == "1"`. Report each
  selected plist by label with PASS/FAIL.
- If zero plists match: print
  `OK: no cline/kanban launchd plists exist yet (Phase 5 creates them) — this check is armed for reuse`
  and treat it as a pass. This is expected today: the current LaunchAgents dir has no cline/kanban entry.
- Exit non-zero if any matching plist lacks the variable.

Finish by printing a single summary line: `check_versions: PASS` or `check_versions: FAIL (<n> problems)`.
