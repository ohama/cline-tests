<objective>
Run the real `cline` binary through the new alias and write down what the stream actually contains.

Purpose: everything measured so far was measured with `curl`. `curl` proves the gateway forwards the
injected parameters; it says nothing about whether **Cline**, driving its own agent loop through
that alias, ends up reasoning. This project has already spent two days on the gap between those two
statements — in v1 a value was correctly written into `providers.json` and the CLI simply never read
that field. Phase 9 deliberately never launched `cline` at all (`GATE-VERDICT.md` §5 records the
deferral, and the human approved it), so this is the first time in the milestone that the actual
consumer is exercised.

`REQUIREMENTS.md` VRF-04 and ROADMAP criterion 6 both say the same thing twice over: **a negative
observation satisfies this requirement.** The deliverable is an observation, not a positive result.
If `reasoning` never appears in the stream, that is a finding of exactly equal standing, and it is
what Phase 11 and Phase 12 need to know before they build a wrapper around this alias.

Output: `phase-10/probe_vrf04_cline.sh`, the captured NDJSON streams, and
`phase-10/VRF-04-OBSERVATION.md`.

**Outcome neutrality:** do not re-run to chase a positive. Re-run only for an *operational* failure —
a timeout, a non-zero exit, an empty stream — and record every attempt either way.
</objective>

<hard_constraints>
1. **Do not write `providers.json`.** The alias is selected with `-m <alias>`, which overrides that
   provider's stored `model` for one invocation only (`apps/cli/src/main.ts:1054-1055`,
   `apps/cli/src/commands/program.ts:47-48,225`). Pointing `providers.json` at `flashnext-plan`
   would break `phase-01/config/verify_config.sh`'s hard `model == "flashnext"` assertion and risks
   the previously-recorded field-normalization loss. The plan asserts the file's sha256 is
   unchanged at the end.
2. **No restart, no config write.** `postflight10` is called with `litellm_restart_expected=0`.
3. **Never `-m flashnext-codex`**, and never let a prompt cause the agent to invoke it. Nothing
   binds port 3000.
4. **`CLINE_NO_AUTO_UPDATE=1` on every invocation**, and `cline --version` recorded immediately
   before and immediately after the runs. It is known that this env var does not reliably prevent
   the detached background `npm update` (CFG-05, carried to v1.2+) — recording the version on both
   sides is the available mitigation, and a version change mid-run invalidates the comparison and
   must be reported rather than ignored.
5. **Do not use `cline --id <session-id>` to resume** — 100% failure reproduced across every argument
   form in this installed version. Any multi-step behavior must happen inside a single invocation.
6. **Do not use `cline config --json`** — it requires a real TTY and fails headlessly.
7. **Polite tenant.** `--max-num-seqs 1`; confirm `in_flight=0` before each run; runs strictly
   sequential, never concurrent; keep the prompt short so the agent finishes in a few turns.
8. **Do not pass any auto-approval flag.** The prompt is chosen so no tool use is needed.
</hard_constraints>

  <action>
Create `phase-10/probe_vrf04_cline.sh` (sources `phase-10/probe_lib10.sh`) and run it.
`new_run_dir10 vrf04`, write `phase-10/results/CURRENT_VRF04_RUN`, `preflight10`.

Record `cline --version` into `"$RUN"/cline-version-before.txt` and
`shasum -a 256 ~/.cline/data/settings/providers.json` into `"$RUN"/providers-before.txt`.

**One fixed prompt for every run**, short, self-contained, and requiring no tool call so no
approval prompt can block a headless run. For example:
`"1부터 20까지의 소수를 모두 더하면 얼마인가? 계산 과정을 간단히 보이고 답을 마지막 줄에 써라."`
Use the same string verbatim in every run — the streams are only comparable if the prompt is
identical.

**Run 1 — the subject.** After confirming `in_flight=0`:
```
CLINE_NO_AUTO_UPDATE=1 cline -P openai-compatible -m flashnext-plan \
  --compaction agentic --json -t 600 "<the prompt>" \
  > "$RUN"/ndjson-plan.log 2> "$RUN"/stderr-plan.log
```
Record the exit code. `-P openai-compatible` selects the already-pinned provider entry
(`baseUrl: http://localhost:4000/v1`, `apiKey: dummy`, `contextWindow: 29000`); `-m` overrides only
the model id for this invocation. `--compaction agentic` matches the project's pinned setting.

**Run 2 — the control.** Identical in every respect except `-m flashnext`, into
`"$RUN"/ndjson-control.log`. Confirm `in_flight=0` again before firing; never run the two
concurrently.

**Run 3 — optional, only if both above completed cleanly and the model is idle.**
`-m flashnext-act`, into `"$RUN"/ndjson-act.log`. ROADMAP criterion 6 accepts `flashnext` *or*
`flashnext-act` as the control; `flashnext` is the truer baseline, so run 3 is a bonus, not a
requirement. Skip it without penalty if anything above was slow or noisy, and record that it was
skipped.

**Extraction, from each stream, written to `"$RUN"/vrf04.tsv`** (one row per run):
1. The documented path — `jq -c 'select(.event.type=="content_start" and .event.contentType=="reasoning")' <log>`.
   Count the events and sum `.event.reasoning | length`. Save the matched events to
   `"$RUN"/reasoning-events-<run>.jsonl`.
2. **A second, broader net**, because relying on one jq path would let a differently-shaped event go
   unseen and a false negative here is the expensive kind of error:
   `jq -c 'select((tostring) | test("reasoning"))' <log> | head -50` into
   `"$RUN"/reasoning-textscan-<run>.jsonl`, plus the raw counts
   `grep -c 'reasoning' <log>` and `grep -c 'reasoning_content' <log>`. Record the distinct
   `.event.type` values seen in each stream (`jq -r '.event.type' <log> | sort | uniq -c`) so a
   reader can tell a stream that carried no reasoning from a stream that carried nothing at all.
3. Total NDJSON line count, the run's exit code, wall-clock duration, and the final assistant text
   if the stream carries one.

If a run exits non-zero, times out, or produces an empty stream, retry it **once** and record both
attempts. That is an operational retry. **Do not retry a run that completed successfully but showed
no reasoning** — that is the observation.

Afterwards record `cline --version` into `"$RUN"/cline-version-after.txt` and re-hash
`providers.json` into `"$RUN"/providers-after.txt`. Both must match their "before" counterparts; if
the version moved, say so loudly in the TSV and in the document — the comparison spanned two
binaries. Close with `flake_window`, `record_verdict` per run, and
`postflight10 "$RUN" <installed cfg sha> 0`.
  </action>

**§3 What this licenses concluding, and what it does not.** Be strict here; this section is the
reason the requirement exists.
- A positive observation licenses: "through this alias, in this Cline version, on this prompt, the
  stream carried reasoning." It does **not** license "reasoning improves output quality" — that is
  USE-03's A/B in Phase 12, deliberately not attempted here.
- A negative observation licenses: "the parameter reaches the model (per `REACH-PROOF.md`) but the
  reasoning did not surface in Cline's stream on this prompt." It does **not** by itself license
  "the alias is broken" — a short arithmetic prompt may simply not trigger visible thinking, and the
  correct next step is stated rather than assumed.
- Either way, record that this is a single-prompt, single-version observation, and that CFG-05 (the
  auto-update problem, deferred to v1.2+) means the binary can move under this conclusion at any
  time. Note whether the version did in fact move between the before/after readings.

**§4 Relationship to PRB-04.** Phase 9 established from source (`cli-v3.0.53`:
`ai-sdk.ts:284-289`, `agent-message-codec.ts:231`) that Cline **re-attaches** reasoning history to
subsequent turns, and measured that doing so costs **0** tokens on this stack (16/16 `delta=0`). If
the captured stream is multi-turn, note whether reasoning events recur across turns — a corroborating
observation of that source finding, from a live process rather than from reading code. If the stream
is single-turn, say that it cannot speak to this and leave it as Phase 9's source-verified result.

**§5 Requirement mapping.** VRF-04 and ROADMAP criterion 6, with the evidence paths, and the
explicit restatement that a negative observation satisfies both — quote the criterion's own wording
(`관찰 결과가 부정적이어도 이 기준은 충족된다`) so no later reader re-opens it as a defect.

**§6 Handoff to Phase 11.** One short list of what a `cline-plan` wrapper author needs from this:
the exact working invocation, whether `-m` per-invocation override behaved as documented,
`providers.json` confirmed untouched, and whatever caveat §3 established.
