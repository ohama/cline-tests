<objective>
Make the rollback real before there is anything to roll back, then put the change in front of the
human who owns the machine.

Purpose: a backup that has never been restored is a hope, not a rollback. This plan takes the
backup, writes the restore as a script with its own integrity check, **runs that exact script
against the live path while the live file is still pristine** — so the restore is exercised at a
moment when getting it wrong costs nothing — and proves the rehearsal was a no-op by hash and by
pid. It also proves the script refuses a corrupted backup, because a restore path that will happily
install garbage is worse than none.

Then it assembles the one document the user asked for: what exactly changes, what goes down while
it changes, for how long, and the literal command that puts it back. `STATE.md` records the
instruction plainly — *"착수 전 사용자에게 변경 내용과 롤백 절차를 먼저 제시할 것."* This plan is
where that happens. Nothing after this plan may write the live config without passing through the
checkpoint here.

Output: `phase-10/backups/config.yaml.<TS>`, `phase-10/BASELINE.txt`,
`phase-10/rollback_config.sh`, `phase-10/ROLLBACK.md`, `phase-10/CHANGE-BRIEF.md`, and a human
approval.

**Outcome neutrality:** the checkpoint has more than one acceptable answer. "Approved" and "not
now — the stack is busy" and "change the alias set first" are all legitimate outcomes of a
correctly-executed plan. What would fail this plan is presenting the change without the diff, or
without a rollback that has actually been run.
</objective>

**`phase-10/rollback_config.sh <backup-path>`** — the only sanctioned way to put the config back:
1. Refuse if the backup path does not exist.
2. Compute the backup's sha256 and compare it against the value recorded in `phase-10/BASELINE.txt`.
   **Mismatch ⇒ refuse and exit non-zero.** A restore script that will install an unverified file is
   a way to make an outage permanent.
3. `cp -p "$BACKUP" /Users/ohama/agent-stack/litellm/config.yaml`.
4. Re-hash the live file and assert it now equals the backup's hash; exit non-zero if not.
5. Print, but do **not** run, the follow-up the operator must issue for the restore to take effect:
   `bash phase-02/infra/restart_service.sh com.ohama.litellm 4000 --timeout 60`.
   Restarting is plan 10-03's privilege; this script only puts bytes back.

**Rehearsal — run it now, for real, against the live path.** The live file is still pristine and the
backup is byte-identical to it, so this is a content no-op; that is precisely what makes now the
right time to exercise it.
- Record the live file's sha256 and `com.ohama.litellm`'s pid immediately before.
- Run `bash phase-10/rollback_config.sh phase-10/backups/config.yaml.$TS`. It must exit 0.
- Assert afterwards: the live file's sha256 **still equals** the BASELINE value; the mirror's sha256
  is unchanged; `com.ohama.litellm`'s pid is unchanged (nothing restarted); the `head -n ANCHOR-1`
  witness hash is unchanged.
- **Negative control — prove the refusal fires.** Copy the backup to `"$RUN"/corrupt.bak`, append a
  junk line to the copy, and run `bash phase-10/rollback_config.sh "$RUN"/corrupt.bak`. It **must**
  exit non-zero and must **not** have written the live file — re-assert the live sha256 immediately
  after. This is the Phase 9 standard applied here: the envelope is believed only once it has been
  seen to fail.
- Write every command, its exit code and the before/after hashes to `"$RUN"/rehearsal.log` and a
  compact `"$RUN"/rehearsal.tsv`.

**`phase-10/ROLLBACK.md`** — short and operational, written from the rehearsal's actual output:
- the two-step procedure (restore bytes, then restart) with the literal commands, copy-pasteable;
- the backup path and its sha256;
- the evidence that step 1 was rehearsed on the live path at a recorded UTC timestamp, exit 0, live

- the evidence that the integrity refusal fires on a corrupted backup;
- what `restart_service.sh` does on failure by itself: `plutil -lint` before touching anything, a

- **what is *not* rehearsed and why**: the restart half of the rollback is exercised for the first
  time in plan 10-03 Task 1, deliberately, on the *unmodified* config — so that if the restart
  mechanism itself is broken, that is discovered while there is still nothing to undo.
