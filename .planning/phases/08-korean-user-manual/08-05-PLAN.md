2. **프로젝트 등록 — 반드시 `workspace/scratch-repo` 안에서 실행한다.** Explain the mechanism,
   because the user will otherwise get it wrong every time: kanban resolves whatever path it is
   given to that path's **git top-level** and registers THAT, so running the CLI from the repo root
   tries to register `/Users/ohama/projs/cline-tests` — the one path `workspace/ALLOWED_REPOS.json`
   permanently forbids (because `bench/` lives under it and SBX-04 requires `bench/` to be
   unreachable from inside the sandbox). Give the working invocation from the transcripts. Mention
   that `workspace/scratch-repo` is now its own git repository for exactly this reason, and that
   the service exports `GIT_CONFIG_GLOBAL` so git inside the sandbox never tries to read
   `~/.gitconfig` — link to `docs/services.md` §5a rather than re-explaining.
   If 08-01's verdict was `NOT-REGISTERED`, replace this section with the verbatim failure, state
   that no project is currently registered, and say plainly that the card/diff/dependency sections
   below are therefore not demonstrable in this deployment.
3. **카드.** The observed card lifecycle: 목록 보기, 만들기, 옮기기, 지우기 — real commands and
   real column names from `card-lifecycle.txt`/`board.txt`. Where a step exists only in the web UI
   and not in the CLI, say which.
4. **diff 리뷰.** How to see a task's changes, from `diff-and-checkpoint.txt`.
5. **`⚠️ [GAP-CHECKPOINT-KANBAN]`.** Kanban's checkpoint is a **per-task working-tree commit**
   (`createWorkingTreeCheckpointCommit`), and it injects `GIT_AUTHOR_*`/`GIT_COMMITTER_*` directly,
   which is why it keeps working even though `GIT_CONFIG_GLOBAL=/dev/null` removes `user.name` and
   `user.email`. This is **NOT** the same thing as cline's own session-level file checkpointing —
   that one is `docs/manual/01-cli.md`. One sentence each; do not merge them.
6. **`⚠️ [GAP-WORKTREE]`** — write exactly the branch that `phase-08/results/WORKTREE_STATUS`
   names:
   - `WORKTREE=AVAILABLE`: describe the per-task worktree flow with the verified command, AND
     state what it cost — the sandbox's `$HOME` protection was narrowed from `file-read*` to
     `file-read-data`, so stat-level metadata under `$HOME` is now visible to sandboxed processes
     while content, directory listing and writes remain denied. The user approved this on
     2026-08-31; see `docs/sandbox-whitelist.md` §9.
   - `WORKTREE=UNAVAILABLE`: state that **worktree 생성은 이 배포에서 지원되지 않는다**, give the
     reason (git realpath-resolves through `/Users/ohama`, which the sandbox denies; three call
     shapes were tested and all fail identically; there is no no-widening fix), and point at
     `docs/sandbox-whitelist.md` §9 for the exact change that would enable it and its exact cost.
     Do not soften this into "아직 확인되지 않았다".
7. **의존 체인.** From `dependency-chain.txt`. If the capability is not reachable from the surfaces
   available, say that instead of describing it.
8. **`⚠️ [GAP-READONLY]`.** Kanban shows the board; it does not expose a write API to remote
   callers, and the agent surfaces run `--no-tools` / `--auto-approve false`. A remotely triggered
   agent cannot modify files. Changing that is a human security decision, not a flag flip
   (`docs/headless-wrapper.md` §4·§8).
9. **재시작과 문제 해결.** The ONLY sanctioned restart is
   `bash phase-02/infra/restart_service.sh com.ohama.kanban 3484`; take-down is
   `launchctl bootout gui/$(id -u)/com.ohama.kanban`. Never `kill`/`pkill`, never
   `launchctl load|unload|kickstart`. Logs are `~/.cline/logs/kanban.log`/`.err` and are never
   rotated; truncate with `: > <파일>`. Standing check:
   `bash phase-05/services/verify_services.sh`.

Gate it: `bash phase-08/manual/check_manual_claims.sh --file 02-kanban.md --out
"$RUN_DIR/gate-02.txt"` → exit 0.
