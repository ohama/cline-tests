<objective>
Extend the two existing house tools so they can actually cover Phase 5's new surfaces, instead of
forking them.

Purpose: `check_versions.sh` Check C was written in Phase 1 and armed for the moment Phase 5
creates plists — but it only ever checked `CLINE_NO_AUTO_UPDATE`. `kanban` has its own separate
gate, `KANBAN_NO_AUTO_UPDATE=1`, and `kanban --update` is a first-class command, so today a
Phase 5 plist could silently float off the pinned 0.1.70 and Check C would still report PASS.
Separately, `restart_service.sh` demands a listening port before it will call a restart healthy —
correct for flashnext/litellm/kanban, impossible for the empty-token telegram service, which
binds nothing. The house rule is absolute: **never write a new launchd restart helper.** So this
plan extends the one that already encodes the async-`bootout` fix that cost this project two
failed live restarts.

Output: two edited scripts, two throwaway fixture plists, and one evidence directory.

**Budget: at most 1 `cline` invocation** — `check_versions.sh` Check B runs `cline config --json`
once per run, and this plan runs the script exactly once (both fixture cases are asserted from
that single run). Run `phase-01/config/verify_config.sh` afterwards and heal with
`apply_provider_config.sh` if it fails.
</objective>

if "cline" in haystack or "kanban" in haystack:
    env = data.get("EnvironmentVariables", {}) or {}
    required = ["CLINE_NO_AUTO_UPDATE"]
    if "kanban" in haystack:

  <name>Task 2: Generalize restart_service.sh for portless labels</name>
  <files>phase-02/infra/restart_service.sh</files>
  <action>
Extend — do not fork, do not copy into `phase-05/`. Accept `none` as the `<port>` argument
(usage line becomes `restart_service.sh <label> <port|none> [--timeout SECONDS]`).

Changes, all guarded so the numeric-port path is byte-for-byte behaviorally identical:
1. Set `PORTLESS=1` when `$PORT` is the literal `none`; otherwise `PORTLESS=0`.
2. Step 3b (teardown poll): when `PORTLESS=1`, skip the `lsof` probe entirely and set
   `TD_LISTEN=""`; the teardown condition becomes "label no longer registered" alone. Keep the
   existing `sleep 3` settle margin and the existing failure message (adjusted to omit the port
   clause when portless). **Do not remove or weaken the poll itself** — it is the fix for
   `launchctl bootout`'s asynchrony, the trap that produced `Bootstrap failed: 5: Input/output
   error` on two consecutive live flashnext restarts.
3. Step 5 (health poll): when `PORTLESS=1`, `state = running` alone is not a pass — a job stuck
   in a KeepAlive restart loop reports `running` on almost every sample. Require instead:
   `state = running` AND a non-empty `pid`, sampled twice at least 10 seconds apart with the
   **same** pid both times. Only then report success. If the pid changes between samples, fail
   with an explicit message saying the job is restarting rather than settling, and (as everywhere
   else in this script) let the EXIT trap print the rollback block.
4. Update the header comment: document `none`, document *why* the pid-stability requirement
   exists, and state that this generalization exists because Phase 5's telegram connector service
   binds no port while its token slot is empty.

Nothing else changes: no `kill`, no `pkill`, no `launchctl load`/`unload`/`kickstart`, and
`plutil -lint` still runs before `bootout`.

Do not bootstrap anything in this task. Verification here is static plus a `--help`-shaped
argument check; the real exercise happens in 05-04/05-05 against the actual new labels, and
against the existing labels only if a regression is suspected (do NOT restart flashnext to test
this change — 104 GiB and ~30s cold load, and Phase 2 already spent two failed restarts there).
