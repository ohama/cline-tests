<objective>
Run one task. Measure it. Then let the user decide what the rest costs.

Purpose: wall-clock for this phase is genuinely unknown. Docker-local harbor execution is
sequential, every turn queues behind everything else on a `--max-num-seqs 1` model server
(~64s TTFT, ~17 tok/s), and most tasks carry a 1800s agent timeout with three at 3600s. Five to
eight of those could be well under an hour or could be an evening. Nobody — including the
planner — can honestly pick that number before one task has been observed. So this plan buys
exactly one data point and then stops.

Output: `bench/runs/<UTC>-phase07/` seeded with the smoke task, a written analysis, a post-run
gate sweep, and `phase-07/bench/SELECTED_TASKS` carrying the user's answer.
</objective>

<house_rules_reminder>
All ten house rules from `07-01-PLAN.md` apply. Specifically for this plan:
- Run in the FOREGROUND with a visible clock. Do not background the harbor call and walk away —
  the whole point is to observe it.
- A long bench run makes Kanban and Telegram sluggish because every request queues on the same
  single-sequence model server. **That is expected, not a regression.** Say so; do not "fix" it,
  do not restart anything, do not touch `--max-num-seqs`.
- If the machine starts swapping or `flashnext` shows signs of memory pressure, STOP the run and
  report. That is a stop-immediately signal, not something to push through.
- `cline` invocation budget this plan: 0. The host binary is never called; the container has its
  own Cline.
</house_rules_reminder>
