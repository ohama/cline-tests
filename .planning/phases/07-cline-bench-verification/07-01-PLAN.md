<house_rules_for_this_phase>
These bind every plan in Phase 7. Re-read them at the start of each plan.

1. **Do not disturb the six live services.** pids at phase start: flashnext 46573,
   role-shim 75548, litellm 48525, kanban 53894, telegram-connect 99162, kanban-proxy 19669.
   Never `kill`/`pkill`/`launchctl load|unload|kickstart`. `phase-02/infra/restart_service.sh`
   is the only sanctioned restart path and **no plan in this phase has any reason to use it.**
   Assert all six pids unchanged at the start and end of every plan.
2. **Port 3000 stays unbound, always.** A pre-existing public Tailscale entry on `:8443`
   forwards to `http://127.0.0.1:3000`. Harbor starts containers; if any of them publishes a
   host port, 3000 becoming bound would make it world-reachable with no login. Check
   `lsof -nP -iTCP:3000 -sTCP:LISTEN` is empty before and after every `harbor run`.
3. **No mutating `tailscale` command, at all.** Not `serve`, not the public-exposure mode
   (whose subcommand name must never appear in this phase's files next to `tailscale`), and
   `serve reset` is FORBIDDEN. Read-only `tailscale status`/`serve status` is fine.
   This phase opens nothing: harbor talks to the Docker daemon and to `127.0.0.1:4000`.
4. **The host posture is untouched and this phase does NOT decide it.** `EXTRA_ALLOW_PATHS`
   stays empty. `--auto-approve` is not flipped on any shipped surface. The escalation decision
   pending since Phase 4 is **not applicable here** and must be recorded as such, not answered:
   harbor's `cline-cli` adapter runs its own throwaway container-side Cline with `--yolo`,
   entirely independent of this project's `sandbox-exec` surfaces. Never route `harbor run`
   through `phase-03/sandbox/run_sandboxed.sh` — it does not invoke the host `cline` at all.
5. **`bench/` stays out of `workspace/ALLOWED_REPOS.json`.** Do not add it; do not add the repo
   root. `bench/runs/CANARY.txt` must still be unreadable from inside the sandbox at phase
   close (SBX-04). Re-assert with `phase-03/sandbox/verify_sandbox.sh`.
6. **The host `cline` must not drift.** The container has its own Cline; the host's pinned
   3.0.53 and `~/.cline/data/settings/providers.json` (top-level `contextWindow: 29000`) must be
   byte-identical at phase close. `cline` invocation budget for the WHOLE phase: **1**, and only
   if a plan explicitly spends it. After any `cline` invocation run
   `bash phase-01/config/verify_config.sh`; on failure heal with
   `bash phase-01/config/apply_provider_config.sh` and re-verify.
7. **This phase does not touch Kanban.** The `~/.gitconfig` sandbox blocker handed over from
   Phase 6 (`phase-06/results/20260830T071532Z-net05/kanban-registration-blocker.txt`) does not
   recur here because nothing is registered with kanban. Say that plainly in the phase doc so a
   later reader does not think the handoff was ignored.
8. **macOS `/bin/bash` is 3.2** — indexed arrays only, no `declare -A`. The executing shell is
   zsh: wrap space-separated-variable word-splitting in `bash -c '...'`.
9. **WORDING-COLLISION TRAP (~12 prior occurrences in this project):** explanatory prose inside
   a file collides with that same file's own verification greps. Before committing any file,
   run this plan's own greps against it. Concretely for Phase 7: never write
   `EXTRA_ALLOW_PATHS` immediately followed by `=`, and never write the public-exposure
   subcommand name on the same line as `tailscale`.
10. **"It ran" is not "it passed."** A task that dies on the container-side context-window
   mismatch proves the plumbing reached the model; it does not prove this stack completes agent
   tasks. Every claim in this phase must name which of the two it is.
</house_rules_for_this_phase>
