  <name>Task 1: Run the selected tasks sequentially, resumably</name>
  <files>bench/runs/&lt;UTC&gt;-phase07-fix/, phase-07/results/&lt;UTC&gt;-gap-batch/</files>
  <action>
Create `RESULTS="phase-07/results/$(date -u +%Y%m%dT%H%M%SZ)-gap-batch"` and `$RESULTS/pre/`.

**Capture the pre-batch drift baselines first**, because Task 2 compares against them and cannot
create them retroactively:
- `shasum -a 256 "$HOME/.cline/data/settings/providers.json"` → `$RESULTS/pre/providers-hash.txt`
  (read-only; never modify that file).
- The host cline version string and `stat` mtime → `$RESULTS/pre/host-cline.txt`.
- `python3` dump of `workspace/ALLOWED_REPOS.json`'s `repos[]` → `$RESULTS/pre/allowed-repos.txt`.
- The six pids and their `ps -o command=` substrings → `$RESULTS/pre/pids.txt`.
- `docker images --format '{{.Repository}}:{{.Tag}} {{.Size}}'` → `$RESULTS/pre/images.txt`.

Then read `phase-07/bench/SELECTED_TASKS_GAP`, ignoring blank lines and `#` comments.

**If it resolves to zero tasks:** that is the documented no-op path (the user chose `stop-here` or
`accept-terminal` at 07-08). Write `$RESULTS/README.md` recording: the chosen option id from
`07-08`'s `decision2.md`, that zero `harbor run` invocations were made in this plan and why, and
that this is not a failure of this plan. Then go straight to Task 2 — the table still needs to be
regenerated and the gates still need to be swept. Do not add tasks to "make the batch worthwhile."

**Otherwise**, for each listed task, in file order:
1. Re-check the disk floor and the six pids before starting. Skip-and-record (do not abort the
   whole batch) if the floor is breached; abort if a pid is missing, because that means a live
   service died and nothing else should proceed.
2. **Resumability:** if `bench/runs/<RUN>/meta/<task>.json` already exists, skip that task and log
   the skip. This makes the batch safe to re-run after an interruption without re-spending.
3. Run `bash phase-07/bench/run_task.sh "<task>"` in the foreground, teed to
   `$RESULTS/logs/<task>.log`, with the outer wall-clock recorded to
   `$RESULTS/logs/<task>.wall_clock_sec`. `CURRENT_RUN` already points at the post-fix run
   directory from 07-07; every task lands there.
4. After each task, append one line to `$RESULTS/ledger.tsv` with tab-separated
   `task`, `verdict`, `wall_clock_sec`, `model_turns`, `slice_bytes`, `max_prompt_tokens` — read
   from the task's own meta record and a live `wc -c` of its server-log slice. This ledger is what
   makes the batch's real cost inspectable afterwards without opening twelve files.
5. Do **not** retry a failed task. A `fail-task`, `fail-context` or `fail-infra` verdict is a
   result, and re-running it buys a second copy of the same result. If a task's `run_task.sh` exits
   non-zero for a harness reason (not a task verdict), record it in `$RESULTS/CAPTURE-GAPS.txt`
   with what was missing, and continue to the next task.
6. Expect Kanban and Telegram to be sluggish throughout — every model turn queues on the same
   `--max-num-seqs 1` server. That is expected, not a regression, and is not a reason to stop.

If the batch's cumulative wall-clock exceeds roughly double what `07-08`'s `cost.md` presented as
its worst case, stop after the current task, record why in `$RESULTS/README.md`, and report — the
user agreed to a cost, not to an open-ended one.
  </action>
