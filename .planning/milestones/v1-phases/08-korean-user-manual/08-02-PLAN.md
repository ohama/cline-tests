  <action>
Write `phase-08/manual/check_manual_claims.sh` — `#!/bin/bash`, `set -uo pipefail`, bash 3.2
(parallel indexed arrays only, **no `declare -A`**), read-only, re-runnable, mutating nothing.

**Scope, stated in the file header:** it scans ONLY `$MANUAL_DIR` (default `docs/manual`). It
never reads `.planning/`, never reads a PLAN.md, and never scans `docs/*.md` outside `manual/`.
This is what keeps the gate from colliding with prose that legitimately quotes a forbidden claim
elsewhere in the repo.

**Interface:**
```
check_manual_claims.sh [--file <name>]... [--out <transcript-path>]
check_manual_claims.sh --negative-control [--out <transcript-path>]
```
With no `--file`, all five documents are checked (this is the phase-close signature). With one or
more `--file`, only those are checked — so a plan that has written one document can gate it
without being blocked by the four not yet written. `--file` takes a basename only; reject
anything containing `/`.

**Checks, one `CHECK <id> PASS|FAIL — <detail>` line each, and a final `CASES <pass>/<total>`:**
- `C1-exists` — each in-scope file exists under `$MANUAL_DIR` and has at least `MIN_LINES`
  (default 60) lines.
- `C2-evidence-pointer` — each in-scope file's first 15 lines contain the literal `근거 문서:`
  AND at least one `docs/` path. This is the anti-duplication rule from 08-RESEARCH.md §B1: every
  manual document points at the engineering record that justifies it instead of restating it.
- `C3-markers` — each in-scope file contains every honesty marker the registry assigns to it.
  Markers are literal ASCII bracket tokens that appear in the visible prose, e.g. a paragraph
  beginning `⚠️ [GAP-REBOOT]`. Implement the registry as two parallel indexed arrays
  (`MARKER_FILE[i]`, `MARKER_TOKEN[i]`) with exactly these pairs:
  ```
  00-getting-started.md : [GAP-CLINE-VERSION] [GAP-REBOOT] [GAP-READONLY] [GAP-PORT3000]
  01-cli.md             : [GAP-PLANMODE] [GAP-CHECKPOINT-CLINE] [GAP-READONLY] [GAP-CLINE-VERSION]
  02-kanban.md          : [GAP-WORKTREE] [GAP-CHECKPOINT-KANBAN] [GAP-READONLY]
  03-mobile.md          : [GAP-IPAD] [GAP-TELEGRAM-INDICATOR] [GAP-TELEGRAM-TOKEN] [GAP-PORT3000]
  04-32k-operations.md  : [GAP-COMPACTION-CONFIG] [GAP-BENCH]
  ```
- `C4-links` — every repo-relative path token appearing anywhere in an in-scope file that starts
  with `docs/`, `phase-0`, `workspace/`, `bench/` or `.planning/` must resolve to an existing
  path. Extract with a `grep -oE` over the union of those prefixes plus
  `[A-Za-z0-9._/-]*`, strip trailing punctuation (`.`, `,`, `)`, `:`, backtick), de-duplicate with
  `sort -u`, and test each with `[ -e ]`. Report every dangling path by name.
- `C5-index` — only when `00-getting-started.md` is in scope: it must reference all four of the
  other manual filenames by name.

**Exit contract** (mirrors the house 3-way discipline): `0` = every check PASS; `1` = at least one
FAIL; `2` = usage error or an in-scope name that is not one of the five.

**`--negative-control` mode:** points `MANUAL_DIR` at `phase-08/manual/fixtures/negative/` and
inverts the expectation — it exits `0` only if the normal run over that fixture directory FAILS,
and exits `1` if the fixture somehow passes (which would mean the gate is fail-open). Create the
fixture directory with copies that are individually broken so that C1–C4 each have at least one
demonstrated detection: one file below MIN_LINES, one file missing its `근거 문서:` header, one
file missing an assigned marker, one file containing a link to `docs/does-not-exist.md`. Fixture
files carry a top-of-file comment saying they are deliberately broken and are never shipped.

**Then prove the gate twice.** Set `RUN_DIR="phase-08/results/$(date -u
+%Y%m%dT%H%M%SZ)-manual-gate"`, `mkdir -p "$RUN_DIR"`, and write that literal path to
`phase-08/results/CURRENT_MANUAL_GATE_RUN` so Task 2 uses the same directory instead of minting a
new timestamp. Save both transcripts there:
- `bash phase-08/manual/check_manual_claims.sh --negative-control` → exit 0 →
  `negative-control.txt`.
- `bash phase-08/manual/check_manual_claims.sh` (bare, all five) → exit **1**, with `C1-exists`
  naming the four-or-five documents that do not exist yet → `bare-preflight.txt`. This transcript
  is the evidence that the gate is armed before any document is written; keep it.

  <action>
`mkdir -p docs/manual`. Write `docs/manual/04-32k-operations.md` in Korean, aimed at a person
USING the system, not at an engineer auditing it. Header block (first 15 lines) must carry a
`근거 문서:` line pointing at `docs/32k-compaction-policy.md` §5·§7,
`docs/cline-max-tokens-findings.md`, `docs/headless-wrapper.md` §3, and `docs/cline-bench.md`
§4·§9 — and a one-line statement that this file is the 사용법 and those files are the 근거.

Required content, all of it:

1. **~64초 프리필 대기.** What it is (32K 근처 요청의 프리필), what the user sees, and — this is
   the part no existing document covers — **how to tell it apart from a stall**: the Kanban card
   stays in In Progress rather than moving to an error state; Telegram shows nothing new because
   the typing indicator is fired once per message and Telegram itself expires it after ~5s with no
   re-fire, and actual response streaming only begins after prefill ends. State plainly that
   silence for ~64s is inside the normal range, and give the user the concrete escalation: if it
   goes far beyond that, run the standing gates (`bash phase-05/services/verify_services.sh`,
   `bash phase-06/net/verify_network.sh --baseline phase-06/results/20260830T051403Z-baseline`)
   before touching anything.
2. **압축은 자동으로 돈다.** `settings.contextWindow = 29000` → 트리거 `26100` (×0.9, once — not
   ×0.81; that two-step fallback only applies when `maxInputTokens` is absent, which is not this
   configuration). The compaction turn issues its own short summarization call (~458 tokens
   measured), so **압축 자체가 추가 지연을 만든다** — a second kind of normal pause the user must
   be able to recognize.
3. **`⚠️ [GAP-COMPACTION-CONFIG]`** paragraph: `contextWindow` must sit at the `settings` TOP
   LEVEL of `providers.json`. `models[]` is the VS Code per-model override path and the CLI does
   not read it — putting the value there is exactly the misconfiguration that produced this
   project's original (now retracted) "32K 에서 작업이 죽는다" conclusion. `29000` rather than
   `32768` because ~3,100 tokens of overshoot must be absorbed; raising it means re-satisfying
   `trigger + 3,100 + max_tokens < MAX_KV_SIZE`. The standing guard is
   `bash phase-01/config/verify_config.sh` — give the user that one command.
4. **작업 예산과 태스크 쪼개기는 더 이상 필요 없다.** Say explicitly that earlier guidance to
   budget ~26k and split tasks is superseded by the 2026-08-30 correction, because compaction
   holds the band and long sessions run to completion (verified at 18 fillers / >30k cumulative).
   Do not re-issue the old advice anywhere in the file, including as a "just in case".
5. **서버 400 은 회복 불가.** If the configuration ever drifts back to the wrong slot, the stack
   returns a `MAX_KV_SIZE` (32768) 400 that Cline's own error classifier does not recognize, so
   there is no self-recovery: **터미널 실패, 재시도하지 말고 작업을 다시 시작한다.** Map it to
   what the user actually sees from the headless wrapper: outcome `context_overflow_terminal`,
   exit code `5` (`docs/headless-wrapper.md` §3).
6. **⌘+클릭이 터치에서는 안 된다.** iPad/iPhone Safari has no modifier-click, so any workflow
   step that assumes ⌘+click must be replaced by the touch equivalent (long-press → 새 탭에서
   열기) or done on the Mac. Cross-reference `docs/manual/03-mobile.md`.
7. **`⚠️ [GAP-BENCH]`** paragraph. Only these claims, and no others: cline-bench의 공식 과제
   요청이 이 스택의 flashnext/litellm 체인에 실제로 도달한다; 파이프라인이 서로 다른 4개 과제에
   대해 반복 동작했다; 이 스택은 관측된 3개 과제 어디에서도 32K 컨텍스트 예산 안에서 과제를
   완료하지 못했다 — 통과 0개. `docs/cline-bench.md` §9 forbids five specific sentences: do not
   write that cline-bench passed, that the official suite was validated, that on-wire prompts were
   captured, that BCH-01 is met, or that this stack can complete a cline-bench task. Re-verify by
   re-reading §9 before you write this paragraph.
8. A short closing "이럴 때는 어디를 보나" table mapping symptom → document/command.
