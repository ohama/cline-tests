<objective>
Build the SBX-01 source of truth and the compiler that turns it into a kernel-enforced Seatbelt
profile, plus the one wrapper every downstream phase will call.

Purpose: `03-RESEARCH.md` proved by `strings` over the actually-installed binary that Cline has
NO native mechanism that can satisfy SBX-02/SBX-03 — `CLINE_COMMAND_PERMISSIONS` and `.clineignore`
do not exist in this build, and `CLINE_SANDBOX`/`CLINE_SANDBOX_DATA_DIR` only relocate config
storage. `sandbox-exec` wrapping the whole process is the only enforcement point, and it was
verified live to intercept a Node process's in-process `fs.*` calls and its `execSync` subprocesses
identically — which is why SBX-02 and SBX-03 collapse into this one artifact. This plan owns the
*subject under test*; plan 03-02 (parallel) owns the test inputs; plan 03-03 (wave 2) proves it.

whitelist at `workspace/ALLOWED_REPOS.json`, and the deliberately-outside-the-whitelist `bench/`
tree.

Write the tests BEFORE the implementation, run them, confirm they fail, then implement until green.
`render_profile()` is a pure function of its arguments — this is exactly the case where a test can
be written before the code exists.

**Step A — write `phase-03/tests/test_gen_sandbox_profile.py`** (pytest, matching the style of
`phase-01/tests/test_parse_result.py`; import the module by path via `importlib` since the source
lives in a sibling directory with a hyphenated parent). Required cases:

  1. `render_profile("/Users/ohama", ["/Users/ohama/.cline", "/p/repo-a"])` returns EXACTLY, in this
     order and no other lines:
     ```
     (version 1)
     (allow default)
     (deny file-read* (subpath "/Users/ohama"))
     (deny file-write* (subpath "/Users/ohama"))
     (allow file-read* (subpath "/Users/ohama/.cline"))
     (allow file-write* (subpath "/Users/ohama/.cline"))
     (allow file-read* (subpath "/p/repo-a"))
     (allow file-write* (subpath "/p/repo-a"))
     ```
     Ordering is load-bearing: SBPL is last-match-wins, so every allow punch-through MUST come
     after the deny-root lines. Assert the index of the first `(allow file-read*` line is greater
     than the index of both deny lines.
  2. Wildcard forms only: assert the rendered text contains no bare `file-write-data`,
     `file-write-create` or `file-read-data` rule — only the `file-read*` / `file-write*` wildcards.
     (Restricting only `file-write-data` would still let a forbidden new file be created.)
  3. Canonicalization (the reproduced bypass from 03-RESEARCH.md Pitfall 2): build a tmp_path tree
     with a real directory `real/` and a symlink `link -> real`, put the SYMLINK spelling in the
     JSON, and assert the resolved list and the rendered profile contain the realpath'd `.../real`
     form and NOT the `.../link` form. Do the same for the protected-root argument.
  4. Validation — `load_allowed_repos` exits non-zero (SystemExit) with a message naming the
     offending entry when: (a) an entry does not exist, (b) an entry exists but is a file not a
     directory, (c) one entry is nested under another (`/a/b` listed alongside `/a`).
  5. Prefix-boundary sanity: given an allowed `/a/allowed`, assert the rendered profile does NOT
     contain a rule for `/a/allowed_extra` — i.e. the generator emits one exact subpath per entry
     and invents nothing. (The kernel's component-boundary handling of `subpath` was verified live
     in research; this test guards the generator side only.)
  6. Empty `repos` list: the generator still emits a valid profile containing the deny-root lines
     and the extra-allow entries — it must NOT emit an empty or deny-less profile, which would be
     a fail-open profile.

**Step B — run `python3 -m pytest phase-03/tests/test_gen_sandbox_profile.py -q` and confirm it
fails** (module missing). Record that it failed.

**Step C — implement `phase-03/sandbox/gen_sandbox_profile.py`** to make them pass. Shape:

  - `load_allowed_repos(path) -> list[str]`: parse JSON, take `data["repos"]`, ignore keys starting
    with `_`, `os.path.realpath()` every entry, `sys.exit(...)` with a message naming the raw and
    resolved forms if an entry is not an existing directory, and `sys.exit(...)` if one resolved
    entry is nested under another (compare with a trailing `os.sep` so `/a/b` vs `/a/bc` does not
    false-positive).
  - `render_profile(protected_root, allow_paths) -> str`: pure, deterministic, no timestamp, no
    file I/O. Emits exactly the 2 + 2 + 2N lines above, newline-terminated.
  - CLI: `gen_sandbox_profile.py --allowed-repos <json> --protected-root <path> [--extra-allow <path>]... --out <file>`.
    The CLI realpaths `--protected-root`, prepends the Cline data dir and each `--extra-allow` to
    the allow list (each realpath'd, each validated as an existing directory), writes a `;;`
    header comment line naming the source JSON and a UTC timestamp ABOVE the `(version 1)` line
    is NOT allowed — SBPL requires `(version 1)` first, so put the `;;` header comment lines
    immediately AFTER `(version 1)` instead, and keep them out of `render_profile()` so the unit
    tests can compare exact text. Header must include `DO NOT EDIT — generated from <json>`.
    On success print the resolved allow list to stderr (evidence for the results dir) and exit 0.
  - `--print-only` flag: write to stdout instead of a file (used by the verifier's negative-control
    test in plan 03-03).

**Step D — run the tests again; all must pass.**

Behaviour:
  - `set -euo pipefail`; resolve its own directory; `source config.env`.
  - Usage: `run_sandboxed.sh [--profile-out <path>] -- <command> [args...]`, and also accept the
    command with no `--` separator for convenience.
  - ALWAYS regenerate the profile first, unconditionally — call `gen_sandbox_profile.py` with
    `--allowed-repos "$ALLOWED_REPOS_JSON" --protected-root "$PROTECTED_ROOT"

    to design out; generation is a sub-millisecond JSON parse).
  - If generation fails, abort with a non-zero exit and a clear message BEFORE running anything —
    fail closed, never fall back to running unsandboxed.
  - Then `exec /usr/bin/sandbox-exec -f "$SANDBOX_PROFILE" "$@"` so the sandboxed process inherits
    the pid and the caller sees its real exit code and stderr untouched.
  - Header comment must document, for Phase 4: (a) the exact invocation form, (b) that the exit
    code and stderr belong to the wrapped command, (c) the stated `(allow default)`/$HOME-only

    (built in plan 03-03) is the standing gate to call before trusting this wrapper, and (e) that
    `EXTRA_ALLOW_PATHS` in config.env is the only sanctioned widening point.

Because `EXTRA_ALLOW_PATHS` is colon-separated and the executing shell is zsh (which does not
word-split unquoted variables the way bash does), do the splitting inside this bash script with
`IFS=:` and an indexed array — do NOT rely on the caller's shell, and do NOT use `declare -A`
(macOS `/bin/bash` is 3.2 and has no associative arrays).

Also add a `--dry-run` flag that regenerates the profile and prints the exact `sandbox-exec` command
line it WOULD exec, then exits 0 without executing — plan 03-03's verifier and Phase 4 use this to
assert wiring without paying for a run.
