<objective>
Register the first of the two new always-on services: Kanban.

Purpose: this is the first time this project ADDS a launchd agent rather than editing one that
already existed, so the whole point is to do it through the house rules — idempotent writer, the
one sanctioned restart helper, evidence to a timestamped directory — and to prove the service
settled rather than merely reported `running`.

Output: the staged plist, an idempotent installer, a live `com.ohama.kanban` service, and evidence.

**Budget: ZERO `cline` invocations.** `kanban --version` is permitted (cheap, does not touch
cline's config) and is worth recording once as the pin check.

**Process hygiene:** the ONLY `kill` in this plan is the single, deliberate SVC-03 KeepAlive test
required by ROADMAP criterion 2 — `kill -TERM <the exact pid launchctl reports>`, never `-9`,
never `pkill`, never a pattern. Killing is a TEST here; it is not the take-down path. The
take-down path is `launchctl bootout gui/$UID/<label>`, and this plan runs it.
</objective>

  <name>Task 1: Stage com.ohama.kanban.plist and write the idempotent installer</name>
  <files>phase-05/plists/com.ohama.kanban.plist, phase-05/services/install_services.sh</files>
  <action>
**`phase-05/plists/com.ohama.kanban.plist`** — match the existing house style exactly (compare
against `~/Library/LaunchAgents/com.ohama.flashnext.plist`, the fullest of the three: keys in
alphabetical order, tab indentation, `KeepAlive` as a **bare boolean**, never the dict form — no
precedent for the dict form exists in this project):

```
EnvironmentVariables:
    PATH                  = /opt/homebrew/bin:/usr/bin:/bin:/usr/sbin:/sbin
    CLINE_NO_AUTO_UPDATE  = 1
    KANBAN_NO_AUTO_UPDATE = 1
KeepAlive             = <true/>
Label                 = com.ohama.kanban
ProgramArguments      = [ /bin/bash, /Users/ohama/projs/cline-tests/phase-05/services/run_kanban_service.sh ]
RunAtLoad             = <true/>
StandardErrorPath     = /Users/ohama/.cline/logs/kanban.err
StandardOutPath       = /Users/ohama/.cline/logs/kanban.log
ThrottleInterval      = 30
WorkingDirectory      = /Users/ohama/projs/cline-tests/workspace/scratch-repo
```

Why each non-obvious choice, as an XML comment block above the dict or in the installer header
(the plist itself must stay `plutil`-clean):
- `PATH` must contain `/opt/homebrew/bin` — `/opt/homebrew/bin/kanban` is a symlink to a
  `#!/usr/bin/env node` script, so without node on PATH the service dies at exec.
- `WorkingDirectory` is the sandboxed workdir, not the repo root: THE CWD RULE
  (`docs/headless-wrapper.md` §6) — a launchd caller that omits it resurrects the Bun/Node startup
  crash, and it will look like a sandbox tightening rather than a cwd bug.
- Log paths live under `~/.cline/logs/` because launchd's `StandardOutPath`/`StandardErrorPath`
  fds are inherited by the sandboxed child, and `~/.cline` is the punched-through directory.
- `ThrottleInterval 30` matches `THROTTLE_INTERVAL` in `phase-05/services/config.env`; the house
  range is 10 (role-shim, litellm) to 60 (flashnext).
- `RunAtLoad true` is the reboot-persistence mechanism (see 05-07 for exactly what that does and
  does not prove).
- No `--port 3000` anywhere, ever (ROADMAP Phase 6 criterion 3).

**`phase-05/services/install_services.sh`** — `install_services.sh <label> [--dry-run]`.
`#!/bin/bash`, `set -euo pipefail`, sources `phase-05/services/config.env`. Steps:
1. Validate `<label>` is exactly `$KANBAN_LABEL` or `$TELEGRAM_LABEL`; anything else exits 2.
2. `mkdir -p "$SANDBOX_WORKDIR" "$SERVICE_LOG_DIR" "$BACKUP_DIR"` — **before** the plist lands.
   `WorkingDirectory` pointing at a missing directory makes launchd fail the job, and
   `workspace/scratch-repo/` is gitignored so a fresh checkout does not have it.
3. `plutil -lint` the STAGED plist; abort if it does not print OK (never install an unlintable
   plist — a booted-out label that then fails to bootstrap leaves the service DOWN).
4. If a live plist already exists and differs, copy it to
   `$BACKUP_DIR/<label>.plist.<UTC timestamp>` first.
5. If the live file is already byte-identical to the staged one, print `unchanged: <label>` and
   exit 0 without writing (idempotent — re-running must be a no-op).
6. Otherwise `cp -p` staged → `$LAUNCH_AGENTS_DIR/<label>.plist`, `plutil -lint` the installed
   copy, print `installed: <label>`.
7. **Do NOT bootstrap.** Print, as the last line, the exact next command:
   `phase-02/infra/restart_service.sh <label> <port|none>`. Single responsibility: this script
   writes files; the one sanctioned helper is what talks to launchd, because it is the only thing
   that encodes the async-`bootout` teardown poll.
`--dry-run` prints what would happen and writes nothing.
  </action>
  <verify>
`plutil -lint phase-05/plists/com.ohama.kanban.plist` prints OK.
`plutil -convert json -o - phase-05/plists/com.ohama.kanban.plist | python3 -c "import json,sys;d=json.load(sys.stdin);e=d['EnvironmentVariables'];assert d['KeepAlive'] is True and d['RunAtLoad'] is True;assert e['CLINE_NO_AUTO_UPDATE']=='1' and e['KANBAN_NO_AUTO_UPDATE']=='1';assert '/opt/homebrew/bin' in e['PATH'];assert d['WorkingDirectory'].endswith('workspace/scratch-repo');assert d['ThrottleInterval']==30;print('OK')"` prints OK.
`grep -c '3000' phase-05/plists/com.ohama.kanban.plist` == 0.
`bash phase-05/services/install_services.sh --dry-run com.ohama.kanban` writes nothing (`ls ~/Library/LaunchAgents/com.ohama.kanban.plist` still absent).
`bash -n phase-05/services/install_services.sh` exits 0; `grep -c 'launchctl bootstrap' phase-05/services/install_services.sh` == 0.
  </verify>
  <done>A house-style plist is staged and lints clean, and an idempotent installer exists that writes files but never talks to launchd.</done>
</task>

   - `launchctl print gui/$(id -u)/com.ohama.kanban > launchctl-print.txt` — must show
     `state = running` and a `pid`;
   - **pid stability**: re-read the pid after 20s; identical (a job stuck restarting reports
     `running` on nearly every sample — `state = running` alone proves little);
   - `lsof -nP -iTCP:3484 -sTCP:LISTEN > lsof-3484.txt` — non-empty;
   - **anti-orphan check**: `ps -o pid=,ppid=,args= -p <the pid launchctl reports> > supervised-proc.txt`
     — the args must show the `sandbox-exec` / `kanban` chain, proving the supervised pid IS the
     real server (the wrapper `exec`s all the way down, so the pid is preserved) and not a parent

     real HTTP status is a pass (kanban auto-generates a remote-access passcode by default and we
     deliberately did NOT pass `--no-passcode`, so a 401/302 is a correct, expected answer; `000`
     is a fail);
   - `lsof -nP -iTCP:3000 -sTCP:LISTEN > lsof-3000.txt` and assert the kanban pid is not in it;
   - `/opt/homebrew/bin/kanban --version > kanban-version.txt` — must still read `0.1.70`.
5. Post-gate: `verify_no_regression.sh` again → `INF03: PASS`, and pids in `$RES/pids-after.txt`
   identical to `pids-before.txt`.

**(a) The KeepAlive test — criterion 2 requires exactly this.**

**(b) The take-down path — tested, not just documented.**
`launchctl bootout gui/$(id -u)/com.ohama.kanban`, then poll until
`launchctl print gui/$(id -u)/com.ohama.kanban` fails (label gone) AND
`lsof -nP -iTCP:3484 -sTCP:LISTEN` is empty. Confirm it STAYS down for 30s (KeepAlive cannot
revive a booted-out job — that is exactly why `bootout` is the take-down path and `kill` is not).
