and write the response policy that the rest of the project will be built on.

3. **세 가지 결과와 대응 방침** — all three, always, with the observed one marked `← 이번 실측 결과`.
   Each needs a concrete, actionable policy, not a sentiment:

   - **① ~26.5k 에서 압축 발동** — the override reached the live compaction check. Policy: the working
     budget per task is roughly `trigger − baseline system prompt (≈5,500 tokens measured)`; compaction
     will summarise and continue but each compaction costs a summarisation round trip; Kanban/Telegram
     must surface "압축 중" as a distinct state; record the measured `tokensBefore → tokensAfter` ratio
     so later phases can predict how much history survives.

   - **② 압축 없이 32,768 에서 서버 400** — the override did not reach the compaction check (128k
     fallback won, trigger ≈103,680). Policy MUST state, concretely:
     * **Cline does NOT self-heal from this.** Its overflow-recovery path classifies an error as
       `context_window_exceeded` only on HTTP 400/413/422 AND a match against 8 hardcoded regexes or the
       literal code `context_length_exceeded`. `mlx_vlm.server`'s body —
       `"Request needs N context tokens (P prompt + M max generation), but MAX_KV_SIZE is 32768."` —
       matches none of them ("context tokens" ≠ "context length/window/limit"; no "exceed"; no "too
       long"; no "reduce the length"). The task simply dies with an unclassified error.
     * Therefore the operational rule is **"작업을 다시 시작한다"**, not "기다리면 회복된다".
     * A hard per-task budget: keep conversations under ~26k tokens; split work into small tasks; start
       a new task rather than continuing a long one.
     * What the surfaces must do: Kanban and Telegram must show the dead-task error rather than a
       silent stall; the headless wrapper (Phase 4) must treat a `MAX_KV_SIZE` 400 as a terminal,
       non-retryable failure and say so in its output.
     * What was deliberately NOT done: no litellm/role_shim clamp was added (out of scope by decision —
       the server already rejects before prefill), and no upstream PR was filed.

   - **③ 그 외** — what exactly was inconclusive (never reached the trigger / timeout / unexpected
     event), and the concrete next diagnostic step (raise `FILLER_COUNT`, check the oracle crosscheck,
     re-probe `max_tokens`). Policy in the meantime: assume ② and follow ②'s rules, because that is the
     conservative posture.

4. **재실행 방법** — the exact commands: `bash phase-01/config/verify_config.sh`,

   * Phase 7 cline-bench task selection must respect the per-task token budget derived here.
