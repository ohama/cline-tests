<objective>
Make Cline talk to the local `flashnext` model through litellm at `http://localhost:4000/v1`, declare
that model's context window as 32768 (overriding Cline's 128k `openai-compatible` fallback), and make
the `flashnext-codex` alias unreachable from any Cline config surface.

Purpose: CFG-01, CFG-02 and CFG-07. This is the config whose effect Plan 06's regression test measures.
If `contextWindow: 32768` does not reach Cline's compaction check, the compaction trigger sits at
~103,680 tokens instead of ~26,542 and every task dies at the 32,768 server wall. Writing the field is
cheap; making it re-appliable and re-verifiable is the actual deliverable, because research observed
`providers.json` silently losing manually-added fields across invocations (RESEARCH.md Pitfall 5).

Output: Two shell scripts (`apply_provider_config.sh`, `verify_config.sh`), a timestamped backup of the
pre-existing `providers.json`, and a captured `cline config --json` snapshot proving what Cline reports.
</objective>

Steps the script performs, in order:

   `contextWindow != 32768`, if `model != "flashnext"`, if `baseUrl` is wrong, or if the string

The script must be safe to run twice in a row with identical end state (idempotent).

<task type="auto">
  <name>Task 2: Write verify_config.sh (pre-run config guard)</name>
  <files>phase-01/config/verify_config.sh</files>
  <action>
Create `phase-01/config/verify_config.sh` (executable, `set -euo pipefail`). This is the guard that
`run_regression.sh` (Plan 03) calls immediately before every real test run, because RESEARCH.md Pitfall 5
observed manually-added `providers.json` fields disappearing after a few `cline` invocations. A regression
run performed against a silently-reverted config would measure the 128k fallback and report a false result.

Behavior:
- Reads `PROVIDERS_JSON="${PROVIDERS_JSON:-$HOME/.cline/data/settings/providers.json}"`.
- Uses `python3` (stdlib) to assert ALL of:
  1. `providers["openai-compatible"]["settings"]["baseUrl"] == "http://localhost:4000/v1"`  (CFG-01)
  2. `...["model"] == "flashnext"`                                                          (CFG-01/CFG-07)
  3. `...["models"]` is a list of length exactly 1, `[0]["id"] == "flashnext"`               (CFG-07)
  4. `...["models"][0]["contextWindow"] == 32768`                                            (CFG-02)
  5. the literal string `flashnext-codex` does not appear anywhere in the file                (CFG-07)
- Additionally greps the whole `~/.cline` tree (`grep -rl 'flashnext-codex' "$HOME/.cline" 2>/dev/null`)
  and fails if any file matches — skip this extra grep when `PROVIDERS_JSON` is overridden.
- On any failure: print `FAIL: <which assertion>` including the actual observed value, and exit 1.
- On success: print `OK: providers.json holds flashnext @ localhost:4000/v1, contextWindow=32768, no codex alias`
  and exit 0.
- Print the expected compaction trigger derived from the observed contextWindow so the number is never
  guessed downstream: `trigger = contextWindow * 0.9 * 0.9` (→ 26542 at 32768), labelled as
  "predicted trigger (RESEARCH.md decompiled formula) — NOT yet proven to fire".
  </action>
