# iPad 확인 체크리스트 (NET-01 / NET-05)

이 문서 하나만 열어서 따라 할 수 있도록 만들어졌다. 다른 문서를 열 필요 없음.

## 0. 두 iPad 는 현재 tailnet 에서 오프라인이다

`ipad-mini-6th-gen-wifi` (마지막 접속 29일 전), `ipad165` (마지막 접속 4일 전) — 둘 다 오래
떨어져 있었으므로 **Tailscale 재로그인이 필요할 수 있다.**

먼저 iPad 에서 **Tailscale** 앱을 연다.
- 성공: 상태가 **Connected** 이고 계정이 `ohama100@` 로 표시된다.
- 실패: **Connected** 가 아니거나 계정이 다르면, 로그아웃 후 `ohama100@` 계정으로 다시
  로그인한다. 로그인해도 안 되면 여기서 멈추고 보고할 것 — 아래 1번부터는 의미가 없다.

## 1. Safari 에서 kanban 주소를 연다

Safari 주소창에 정확히 이 URL 을 입력한다:

```
https://ohama-2.tail318f12.ts.net:8444/
```

- **성공:** 칸반 보드가 바로 뜬다 — 암호(passcode) 입력창이 없고, 인증서 경고도 없다.
- **실패:**
  - 인증서 경고("이 연결은 비공개 연결이 아닙니다" 등)가 뜬다 → tailnet 인증서가 아니라 다른
    인증서를 보고 있다는 뜻. 재로그인부터 다시 확인할 것.
  - 암호(passcode) 입력창이 뜬다 → kanban 이 아니라 다른 무언가에 접속됐거나 설정이 바뀐
    것이다. 즉시 보고할 것 — 이건 이 phase 의 핵심 보장(무인증)이 깨진 것일 수 있다.
  - "이 사이트에 연결할 수 없음" / 타임아웃 → Tailscale 연결 상태(0번)부터 다시 확인.

## 2. 실제로 카드와 diff 를 볼 수 있는지 확인한다

**이것이 NET-01 의 진짜 기준이다 — "페이지가 뜬다" 는 것만으로는 부족하다.**

- 카드 목록이 화면에 보이는가?
- 카드 하나를 열어서 diff(변경 내용)를 실제로 스크롤하며 읽을 수 있는가?
- 탭/스크롤 동작이 iPad 화면 폭에서 자연스럽게 되는가(가로 스크롤이 깨지거나 글자가 잘리지
  않는가)?

세 가지 모두 "예" 여야 NET-01 이 통과한 것이다. 하나라도 "아니오" 면 무엇이 안 되는지 구체적으로
적어 보고할 것(예: "카드는 보이는데 diff 패널이 화면 밖으로 밀려서 안 보임").

## 3. NET-02 확인 — LAN 에서는 아예 접근할 수 없어야 한다

iPad 의 Tailscale 을 끄거나(비행기 모드가 아니라 Tailscale 앱에서 **Disconnect**), Tailscale 이
설치되지 않은 다른 LAN 기기에서 이 주소를 연다:

```
http://192.168.75.108:3484/
```

- **성공:** 아예 연결되지 않는다("사이트에 연결할 수 없음", 타임아웃, 연결 거부 등 — 무엇이든
  "응답이 온다" 가 아니라 "응답이 아예 없다"). **성공 조건은 "거부됨(항의 응답)"이 아니라
  "가는 길 자체가 없음"이라는 점을 유의할 것** — 서버가 문을 닫아건 게 아니라, 애초에 그 문으로
  가는 길이 없다.
- **실패:** 무엇이든 응답이 온다 — 로그인 화면이든, 에러 페이지든, 보드 자체든 — 이건 LAN 에서
  뭔가가 새어 나오고 있다는 뜻이다. **즉시 보고할 것.**

확인 후에는 iPad 의 Tailscale 을 다시 **Connect** 로 돌려놓을 것.

## 4. NET-05 확인 — 긴 대기 중 상태가 보이는지

압축 트리거(약 26,100 토큰) 근처의 긴 요청을 하나 보내고, 프리필 대기(약 64초) 동안 관찰한다.

**a. 칸반 카드**가 **In Progress** 칼럼에 계속 머무는지 확인한다(멈춘 것처럼 보이거나 에러
상태로 바뀌지 않는지).

**b. Telegram 대화에서 무엇이 보이는지** — t=10초, t=30초, t=64초 각 시점에 실제로 본 것을 그대로
적는다.

**무엇이 보일 것이라고 미리 적지 말 것.** 06-05 의 결정 결과에 따라 이 항목은 아직 아무도
확인하지 않은 열린 질문이다: 정적 근거(typing 표시 호출이 메시지당 1회뿐이고 Telegram 자체가
약 5초 뒤 소멸시키며, 재발화 로직이 없고, 실제 응답 스트리밍은 프리필이 끝난 뒤에야 시작됨)는
"64초를 버티지 못할 확률이 높다"는 추정만 줄 뿐, 실제로 누구도 지켜본 적이 없다. **이 트라이얼을
직접 실행하려면** `phase-06/results/20260830T071532Z-net05/decision.md` 의 7단계 체크리스트
(BotFather 토큰 발급 → 숫자형 사용자 ID 확인 → plist 주입 → 첫 실행 로그의 `unknown option`
감시 → t=10/30/64초 관찰 → 정리)를 그대로 따를 것 — 이 문서와 별개로, 언제든 사용자가 직접
수행할 수 있게 남겨둔 항목이다.
